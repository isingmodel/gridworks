# Gridworks — Project Bible

`Gridworks`는 지역 전력회사를 운영하며 발전소, 송전망과 변전소를 건설하고, 폭염과 설비
사용불가 속에서도 필수시설을 지키며 기말 현금을 최대화하는 싱글 플레이 전력망
건설·운영 전략 게임이다. 실제 전달한 전력은 수입이 되고, 공급하지 못한 전력은 잃은
수입과 보상 비용이 된다. 안전 기준을 먼저 통과한 뒤에만 경제 결과를 비교한다.

현재 승인된 개발단위는 완성형 1.0이 아니라 10~15분짜리 **첫 플레이 검증판**이다. 디버그
2D 지도, 기존 발전소, 마을·병원, 두 authored 회랑과 예고된 고장만으로 “플레이어가 더
비싼 독립 경로에 실제로 돈을 쓸 만큼 고민하는가”를 사람 플레이에서 확인한다. 이 단계에는
자유 배선, DC 전력조류, 정식 밸런스 자동화, 저장·리플레이와 3D 제작이 없다.

1.0은 공간 건설과 신뢰도 계획에 집중한 후보 목표다. 첫 검증판을 통과한 뒤에도 전체 목록을
자동 구현하지 않고, 적응형 점검에서 증거상 필요한 기능 축 하나만 다음 단위로 연다. 경제는
건설·판매·발전·대응·수리·보상을 한 현금 원장으로 설명하고 잃은 판매는 진단값으로만 둔다.
프로젝트 금융은 장기 방향과도 분리한다.
구현 기준은 `Godot 4.7.1 .NET + C#`이고 게임 규칙은 엔진에 의존하지 않는 순수 .NET 코드에 둔다.

1.0 이후의 우선 제품 방향은 일반 발전원 수집이 아니다. 플레이어는 원전을 직접 입지·건설하고,
외부 데이터센터 프로젝트의 부지·서비스분율·계통 접속·냉각상태를 승인하고 조정한다. 두 시설은
단일 냉각수 제약을 공유한다. 수원지 최대거리 안의 데이터센터는 수랭·공랭을 전환할 수 있고,
물을 절약하면 계통 전력 피크가 커진다. 이 확장은 1.0 검증 전에는 구현하거나 기반을 선구축하지
않는다.

이 저장소는 게임을 이해하고 현재 무엇을 검증할지 결정하는 완결된 기획 패키지다. 외부
문서 없이 현재 범위와 장기 방향을 이해할 수 있어야 한다.

## 보조 콘셉트 스케치

도형을 사용한다. 이미지가 없어도 문서의 상황·규칙·행동·결과만으로 구현할 수 있어야 하며,

## 역할별 권위

| 영역 | 권위 | 경계 |
|---|---|---|
| 현재 구현 범위·완료조건 | `SCOPE_0_PLAYABLE.md` | 현재 게이트와 충돌하면 항상 우선 |
| 첫 코드 전 Scope 0 fixture 숫자 | `SCOPE_0_PLAYABLE.md`의 표·oracle | 첫 코드가 생길 때까지만 |
| 첫 코드 후 Scope 0 fixture 숫자 | `data/scenario.json` | 단일 기계 권위; 범용 schema는 아직 없음 |
| 제품 원칙·개방된 시스템 규칙 | `GAME_DESIGN_KO.md` | 현재 Scope 0를 확장하는 허가가 아님 |
| 미개방 후보 경계 | `SCOPE_1_0.md`, `POST_1_0.md` | 적응형 점검 전에는 구현하지 않음 |
| 화면 언어·이미지 제작 | `VISUAL_PRODUCTION_SPEC.md` | 규칙·숫자를 재정의하지 않음 |

PNG는 의도와 구도를 전달하는 비권위 시각 참고 자료다. 글자나 숫자가 권위 문서와 다르면
해당 영역의 권위를 따른다.

통화 단위 `M`, 전력 단위 `MW`, 에너지 단위 `MWh/GWh`는 모든 문서와 화면에서 같은 의미로
사용한다. 시간은 현재시각 `DAY 75 16:00`, 기간 `완공까지 52일`, 기한 `마감까지 12일`처럼
의미를 붙여 표시한다.
