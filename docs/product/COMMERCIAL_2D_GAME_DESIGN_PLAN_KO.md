# Gridworks — 상용 2D 게임 재기획서

> 문서 상태: **제품 재기획 제안**
> 작성 목적: 현재 내부 후보를 실제 판매 가능한 소형 2D 전략 게임으로 발전시키기 위한 제품·게임
> 디자인 기준을 정한다.
> 권한 경계: 이 문서는 새 구현을 승인하지 않는다. 현재 구현 권한은 루트 `README.md`와 활성
> 범위 계약이 계속 소유한다. 이 제안을 채택할 때 별도 범위 계약과 새 저장·콘텐츠 버전을 열어야 한다.

## 0. 결론

현재 Gridworks는 **좋은 기술 핵심 구간 완성본**이다. 분기·합류, 공유 용량, 사고 미리보기, 직접
선로 건설과 설명 가능한 병목은 이미 경쟁력 있는 기반이다. 그러나 콘텐츠 선택과 최종 표현까지
검증하는 **상용 핵심 구간 완성본**은 아직 아니다.

```text
기술적으로 동작하는 누적 배선 퍼즐
≠
플레이어가 자기 도시의 미래를 선택하는 전략 게임
```

문제는 설비 종류나 계산식이 부족해서가 아니다. 현재 여덟 임무가 대부분 `수요를 읽는다 → 선로를
추가한다 → 즉시 완공한다 → 평상시와 사고 조건을 통과하는지 확인한다`로 반복되며, 시간·돈·사건과
이야기가 서로 다른 결정을 만들지 못한다. 결과 문장도 실제 망의 차이를 충분히 기억하지 않는다.

따라서 출시 방향은 대형 전력회사 시뮬레이터가 아니라 다음과 같은 **소형 프리미엄 2D 인프라
전략·퍼즐 게임**으로 고정한다.

> 성장하는 도시와 예고된 위기 사이에서, 지금 가장 싼 선이 아니라 다음 약속까지 지킬 망을
> 설계한다.

핵심 재설계는 일곱 가지다. 1·2번은 이번 제품 제안의 새 기반이며, 4·5번은 상용 핵심 구간에서
재미와 단순성을 먼저 판정할 우선 가설이다.

1. 보이는 격자와 셀 맞춤을 없애고 지형 위에 전신주·변전소를 자유롭게 배치한다.
2. 전선, 변전소 주기기와 전신주 접속부의 연속·비상 열 한계를 국면 사이에 이어지는 판단으로 만든다.
3. 공사 초안이 평상시·예고 상황의 경로와 열 상태를 어떻게 바꾸는지 발주 전에 보여준다.
4. 한 장을 두세 개의 결정 경계로 나누고 공사기간을 실제 기한과 연결한다.
5. `반드시 지킬 안전 의무`와 `선택할 수 있는 도시 약속`을 구분한다.
6. 장 전체를 폐기하지 않고 최근 공사나 공사 묶음을 제한적으로 되돌릴 수 있게 한다.
7. 결과 카드와 에필로그가 실제 공급원·경로·열여유·지킨 약속을 말하게 한다.

전력시장, 기술 트리, 실시간 급전, 절차 생성과 복잡한 경제는 추가하지 않는다. **깊이는 별도
재화를 계속 더하는 대신, 자유롭게 놓은 같은 선로가 비용·기한·공간위험·열여유·미래 가치에 서로
다른 답을 갖는 데서 만든다.**

## 1. 현재 후보에 대한 제품 판정

### 1.1 이미 가치가 있는 기반

- 전신주·변전소에서 세 갈래 이상 분기하고 다른 경로와 합류할 수 있다.
- 발전원, 선로, 전신주와 변전소의 사용량·정격·접속 여유가 실제 공급 계산에 참여한다.
- 평상시와 작성된 사고 상태를 같은 망에서 비교할 수 있다.
- 실패가 단순한 `전력 부족`이 아니라 첫 경로 병목과 부족량으로 설명된다.
- 같은 도시 지도, 자산, 자금과 명령 기록이 여러 임무에 이어진다.
- 마우스와 키보드로 직접 선로를 만들고 저장·재개할 수 있다.

이 기반은 폐기하지 않는다. 특히 결정론적 평가기는 플레이어에게 “왜 이렇게 됐는가”를 설명할 수
있다는 점에서 Gridworks의 가장 강한 차별점이다.

### 1.2 상용 게임으로 부족한 지점

| 영역 | 현재 상태 | 플레이어가 느끼는 문제 |
|---|---|---|
| 임무 리듬 | 건설 뒤 평상시·사고 조건을 한 번에 판정 | 여덟 장이 같은 시험 문제의 숫자 변형처럼 보임 |
| 시간 | 공사 시각은 증가하지만 실패 기한이 없음 | 공사기간이 전략 자원이 아니라 장식이 됨 |
| 경제 | 장별 지원금과 건설비만 존재 | 돈이 선택보다 시행착오 벌금처럼 작동함 |
| 목표 | 대부분 모든 요구 부하의 전량 공급 | 무엇을 우선하고 포기할지 결정할 여지가 적음 |
| 사건 | 언제든 미리 보는 정적 제외 목록 | 위기가 국면 변화보다 두 번째 정답표로 느껴짐 |
| 회복 | 초안 취소, 장 재시작, 과거 장 되감기 | 오래 플레이한 뒤 한 실수를 고치기 위해 너무 많이 되돌아감 |
| 이야기 | 고정 브리핑·사건·결과 한 벌 | 다른 망을 만들어도 도시와 인물이 같은 말을 함 |
| 보상 | 성공 카드와 다음 장 | 직접 만든 망이 도시를 바꿨다는 감각이 약함 |
| 공간 | 33×21 셀과 보이는 격자에 배치 | 도시 지형보다 보드 칸을 채우는 느낌이 강함 |
| 용량 | 고정 정격을 넘으면 즉시 경로 부적격 | 더운 날·지속 과부하·냉각을 계획할 여지가 없음 |
| 표현 | 계통도·텍스트 중심 | 살아 있는 도시보다 내부 운영 도구처럼 보임 |
| 검증 | 자동검사와 작은 LLM 관찰 중심 | 재미·문체·가치에 대한 사람 증거가 없음 |

### 1.3 정직한 성숙도

현재 macOS ZIP은 기술적 **내부 후보**이고, 상업 제품 성숙도로는 **상용 핵심 구간 완성 이전의
플레이 가능한 기준선**이다. 패키지가 설치되고 캠페인이 끝난다는 사실은 유료 게임으로서 반복
동기, 감정적 보상, 콘텐츠 밀도와 전문적인 연출을 증명하지 않는다.

기존 후보의 자동검사·패키지·LLM 관찰은 역사적 기준선으로 보존하되, 새 제품이 통과했다는 증거로
합산하지 않는다.

## 2. 제품 정의

### 2.1 장르와 규모

| 항목 | 결정 |
|---|---|
| 장르 | 싱글 플레이 2D 전력망 건설 전략·퍼즐 |
| 제품 규모 | 한 도시를 끝까지 책임지는 소형 프리미엄 게임 |
| 핵심 입력 | 데스크톱 마우스·키보드 |
| 핵심 공간 | 보이는 격자 없이 자유 배치하는 청류시 지도 한 장, 장별 도시·날씨 변화 |
| 첫 완주 목표 | 약 2.5~4시간의 제작 가설, 사람 플레이로 확정 |
| 추가 체류 | 다른 설계 재도전은 선택 사항이며 고정 시간을 약속하지 않음 |
| 데모 가설 | 첫 공급 자유 배치와 5장 열 판단을 잇는 30~45분 편집본 |
| 출시 우선순위 | 한국어 macOS 직접 배포 후보, 이후 플랫폼은 별도 검증 |

정확한 플레이 시간과 가격은 상용 핵심 구간의 사람 관찰과 별도 시장 검토 전에는 광고 문구로
확정하지 않는다. 플레이 시간을 맞추려고 결정 경계나 후일담을 늘리지 않는다. 한 지도와 여덟
임무로 8~12시간을 억지로 늘리면 같은 판단이 반복될 가능성이 높다. 그 길이를 원한다면 두 번째
도시나 별도 운영 체계가 필요하므로 이번 제품 범위를 넘어선다.

### 2.2 대상 플레이어

- 네트워크·물류·도시 건설 퍼즐을 좋아하는 플레이어
- 숫자는 읽을 수 있지만 전력공학 지식을 전제로 하지 않는 플레이어
- 실시간 손놀림보다 생각하고 계획하는 시간을 선호하는 플레이어
- 짧고 완결된 작가형 캠페인과 자기 설계의 결과를 좋아하는 플레이어

실제 계통운영 교육, 전력시장 경영, 공학 계산기나 무한 샌드박스를 기대하는 사람에게는 맞지
않는다. 상점 설명과 첫 도움말에서 `22.9 kV급 지역망을 단순화한 결정론적 계획 게임`임을 분명히
한다.

### 2.3 플레이어 판타지

> 내가 그은 선이, 내가 보지 못하는 사람들의 평범한 밤을 지킨다.

플레이어의 성장은 더 큰 설비를 해금하는 과정이 아니다.

```text
연결하는 사람
→ 두 경로를 구분하는 사람
→ 공유 용량을 배분하는 사람
→ 아직 오지 않은 위기를 준비하는 사람
→ 자기 망을 믿고 계획정지를 승인하는 책임자
```

## 3. 디자인 기둥

### 3.1 직접 만든 망

선로는 자동 생성되지 않는다. 플레이어가 시작점, 중간 전신주, 끝 접속점을 직접 고르고 분기와
합류를 만든다. 전신주와 변전소는 셀이 아니라 실제 지형 위 원하는 위치에 놓는다. 지도에 남은
망의 모양 자체가 플레이 기록이 된다.

### 3.2 미리 부숴 보는 설계

위기는 숨은 주사위가 아니다. 앞으로 멈출 설비, 위험구역과 시각을 알려준다. 플레이어는 평상시와
예고 상황을 오가며 자기 망을 사전에 시험한다. 실패는 기습이 아니라 예측하지 못한 설계 부채다.

### 3.3 짧은 길, 큰 책임

좋은 선택은 모든 면에서 우월하지 않다.

- 짧은 강변 회랑: 싸고 빠르지만 침수 공통위험을 가진다.
- 긴 고지대 회랑: 비싸고 늦지만 공간적으로 독립적이다.
- 일반선: 초기 투자비가 낮지만 큰 수요를 한 경로로 보내기 어렵다.
- 보강선: 여유가 크지만 다음 공사의 자금을 줄인다.
- 공유 간선: 효율적이지만 한 병목과 사고의 영향이 커진다.
- 독립 경로: 안전하지만 접속 자리와 공사기간을 더 쓴다.

### 3.4 열여유는 다음 국면의 자산이다

같은 2.5 MW라도 계속 보내는 것과 한 비상 국면에만 보내는 것은 같은 선택이 아니다. 선로 도체,
변전소 주기기와 전신주 접속부는 연속 한계 안에서는 계속 쓸 수 있지만, 비상 한계를 사용한 다음
국면에는 보호정지된다. 지금 도시 약속을 지키려고 쓴 열여유가 다음 정비나 사고 국면의 가용망을
바꿀 수 있다.

화면은 실제 섭씨온도를 가장하지 않는다. `현재 사용 / 연속 한계 / 비상 한계 / 다음 경계 상태`만
보여주며, 플레이어는 모든 국면을 발주·승인 전에 미리 확인한다.

### 3.5 실패는 설명되고 고칠 수 있다

플레이어가 틀렸다는 사실보다 **어떤 약속이 어느 첫 병목 때문에 깨지는지**가 먼저 보여야 한다.
잘못을 이해한 뒤에는 현재 판단 지점으로 돌아가 고칠 수 있어야 한다. 여러 장을 되감는 기능은
최후의 복구 수단이지 기본 편집 도구가 아니다.

### 3.6 기술 결과는 사람의 변화로 끝난다

병원의 1.2 MW는 수술실과 중환자실이고, 정수장의 0.9 MW는 식수이며, 주거지 부하는 폭염 속
냉방이다. 결과는 숫자를 숨기지 않지만 숫자만으로 끝내지도 않는다.

## 4. 핵심 플레이 구조

### 4.1 장 단위 순환

```text
도시의 변화와 이번 약속을 읽는다
→ 앞으로 올 수요·정비·재난을 확인한다
→ 현재 망의 실제 공급 경로·열여유·병목을 감사한다
→ 서로 다른 공사안을 초안으로 비교한다
→ 비용·완공시각·평상시·예고 상황의 경로와 다음 경계 상태를 보고 발주한다
→ 다음 결정 경계로 진행한다
→ 변화한 수요 또는 사고에 대응한다
→ 지킨 의무·미룬 약속·남은 여유를 확인한다
→ 실제 망과 결과를 다음 장으로 넘긴다
```

### 4.2 한 번의 공사 순환

```text
수요처 또는 병목을 선택한다
→ 발전원부터 수요처까지 현재 경로를 한 번에 본다
→ 지형 위에 변전소 또는 선로 초안을 자유롭게 그린다
→ 가상 완공 뒤 모든 공개 국면의 결과를 본다
→ 비용·기간·접속 자리·경로의 최소 남은 한도를 확인한다
→ 발주한다
→ 완공 연출과 함께 실제 공급 변화가 나타난다
```

### 4.3 한 장의 국면

한 장은 실시간 시뮬레이션이 아니라 두세 개의 작성된 결정 경계로 구성한다.

```text
브리핑
→ 첫 공사 창구
→ 수요 또는 도시 변화
→ 두 번째 공사 창구
→ 예고 상황 승인
→ 실제 사건과 결과
```

이 구조라면 공사반·배속·실시간 달력 시스템 없이도 “짧고 빠르지만 위험한 회랑”과 “길고 늦지만
독립적인 회랑”을 비교할 수 있다.

## 5. 출시 깊이를 만드는 최소 시스템

### 5.1 계획 효과 미리보기

공사 초안을 가상 완공한 뒤 새 열 규칙을 포함한 하나의 결정론적 규칙 평가기를 초안과 실제 상태에
똑같이 사용한다. 발주 전 패널은 다음을 보여준다.

- 표시 구간 길이, 설비 점유 외곽선과 배치 판정
- 비용과 완공 예정 경계
- 접속 수의 현재값과 완공 뒤 값
- 새로 공급되거나 공급이 끊기는 수요처
- 공급원이 바뀌는 수요처
- 해결되는 첫 병목과 새로 생기는 첫 병목
- 각 공개 국면의 경로 최소 남은 한도와 보호정지 예상
- 예고 상황에서 필수 의무를 지킬 수 있는지

추천 좌표, 자동 경로와 “정답” 표시는 금지한다. 결과를 투명하게 보여주되 설계를 대신하지 않는다.

### 5.2 수요별 경로 감사

수요처 하나를 선택하면 지도에서 다음을 한 번에 강조한다.

```text
사용 발전원
→ 현재 사용 중인 선로·전신주·변전소
→ 가장 작은 용량 여유와 열여유
→ 수요처
```

예고 상황에서는 평상시 경로를 흐리게 남기고, 끊긴 지점과 실제 우회 경로를 비교한다. 공급되지
않으면 충분한 발전원이 가진 경로의 첫 병목을 우선한다. 회색 선은 `단절`이 아니라 `현재 미사용`임을
명확히 표시한다.

### 5.3 격자 없는 자유 배치

화면에는 건설 격자와 셀 좌표를 표시하지 않는다. 플레이어는 지형 위 원하는 위치에 변전소와
전신주를 놓고 직선 선로 구간으로 잇는다. 다만 자유 배치가 픽셀 단위 숨은 최적화가 되지 않도록
규칙 권위는 다음처럼 고정한다.

- 규칙 엔진의 위치는 정수 고정소수점 세계 좌표다. 설계 지도 거리 1단위를 100 내부 단위로 두고,
  입력은 규칙 명령 직전에 가장 가까운 내부 단위로 한 번만 양자화한다.
- 렌더러의 부동소수점·화면 픽셀과 카메라 위치는 비용, 거리, 충돌, 저장과 급전 결과에 참여하지 않는다.
- 선로 정수 길이는 두 점 차이의 제곱합에 올림 정수제곱근을 적용하고, 경로 길이는 구간 길이의 합으로
  계산한다. 비용·기간·경로 동률 판정은 이 규칙 정수만 사용하고 화면에는 같은 값의 읽기 쉬운 단위를
  표시한다.
- 충돌·수면·건물·위험구역 판정은 고정소수점 기하가 권위다. 경계 접촉도 겹침으로 보며, 화면에는
  실제 점유 외곽선과 작은 안전 여백을 그려 판정이 바뀌기 전에 이유를 보여준다.
- 기존 접속점 가까이에서는 화면 거리 기준의 부드러운 자석 맞춤을 제공한다. 후보가 겹치면 `Q / E`로
  순환하고, 화면이 거리 뒤 안정 식별자 순서로 확정한 접속점 식별자를 규칙 엔진에 전달한다. 규칙
  엔진은 픽셀을 모른다.
- 선로는 전신주 사이의 직선 다중구간이다. 곡선 편집, 자동 경로와 자동 전신주 배치는 없다.
- 각 구간은 양의 길이와 선종의 최대 경간을 만족하고, 건물이나 제3 설비 점유영역을 관통할 수 없다.
- 시각적으로 교차한 두 선은 접속점이 없으면 연결되지 않는다. 선로 몸체에는 맞춤하지 않으며, 같은
  양끝점의 중복 구간과 양의 길이로 포개지는 공선 구간은 허용하지 않는다.
- 발주 전 전신주는 끌어 옮길 수 있고 마지막 점을 되돌릴 수 있다. 완공 설비의 자유 이동은 하지 않는다.

각 설비 형식은 단순 원형 점유반경 하나를 가진다. 신규 설비의 점유영역 전체가 지도 안에 있고,
다른 설비·건물·수면과 닿거나 겹치지 않아야 한다. **강 위에는 신규 전신주와 변전소를 지을 수 없지만,
육지의 두 접속점 사이 선로는 강을 건널 수 있다.** 작성된 교량 기초 위 고정 설비만 예외이며
플레이어가 같은 예외를 새로 만들 수는 없다. 위험구역은 배치를 막지 않고, 설비 점유영역이나 선로
구간이 닿으면 예고 사고 노출로 표시한다.

### 5.4 설비 열 한계와 국면 사이 열 상태

열은 실시간 온도 시뮬레이션이 아니라 작성된 운영 국면 사이의 결정론적 계획 자원이다. 실제로
가열되는 대상을 다음처럼 정확히 부른다.

| 게임 오브젝트 | 플레이어에게 보이는 이름 | 대표하는 설비 |
|---|---|---|
| 전선·선로 구간 | 선로 열여유 | 도체의 계획상 열 한계 |
| 변전소 | 변압기 열여유 | 변압기·모선·인출 설비 중 제한 요소 |
| 전신주 | 접속부 열여유 | 단자·퓨즈·개폐기·분기 접속 장치 |

목재나 콘크리트 기둥 자체가 전력 때문에 뜨거워진다고 표현하지 않는다. 발전원은 기존 출력용량만
사용하며 첫 출시의 열 모델에 넣지 않는다.

각 열 설비 형식은 `연속 한계`와 `비상 한계` 두 값만 가진다. 캠페인은 순서가 고정된 작성 운영
국면을 소유하고, 폭염 국면은 두 한계를 데이터에 적힌 현재값으로 낮출 수 있다. 열 상태는 연속
숫자가 아니라 다음 네 가지뿐이다.

| 상태 | 현재 국면 | 다음 경계 |
|---|---|---|
| 연속 운전 | 사용량이 연속 한계 이하 | 계속 사용 가능 |
| 비상 운전 | 연속 한계 초과·비상 한계 이하 | 다음 국면 보호정지 |
| 보호정지 | 사용 불가, 무부하 냉각 | 한 국면을 쉰 뒤 복귀 |
| 한도 초과 | 비상 한계 초과 | 경로 부적격 |

새 설비는 `연속 운전 가능` 상태에서 시작한다. 비상 운전한 설비는 현재 국면의 공급을 끝까지
유지한 뒤 다음 국면 전체에서 보호정지·냉각되고, 그 국면 종료 뒤 자동 복귀한다. 정확히 연속 한계인
사용은 비상 운전이 아니다. 수동 차단기, 수리반, 화재, 영구 손상, 섭씨온도, 0~100 축열 게이지와
실제 차단 초 계산은 없다. 같은 밤에는 이 이산 상태를 이어 쓰고, 긴 장간 시간경과가 있으면 그
사실과 함께 모든 설비를 복귀시킨다.

각 국면 경계는 다음 순서를 한 번만 실행한다.

1. 이전 보호정지와 작성된 사고 사용불가, 해당 국면의 연속·비상 한계를 적용한다.
2. 현재까지 예약된 사용량을 포함해 모든 발전원·단순 경로 후보를 비교하고 부하를 순서대로 배정한다.
3. 모든 부하 배정 뒤 공유 선로·변압기·전신주 접속부의 최종 합산 사용량을 확정한다.
4. 비상 운전 설비를 다음 국면 보호정지로, 이번 국면을 쉬었던 설비를 그다음 국면 복귀로 기록한다.

비상 열여유는 아무 수요나 자동으로 소비하지 않는다.

| 수요·국면 | 허용 경로 |
|---|---|
| 평상시의 안전 의무 / 모든 국면의 운영 기록 수요 | 연속 운전만 |
| 지키기로 확정한 도시 약속 | 연속 → 비상, 비상 사용은 승인 전에 직접 확인 |
| 이름 붙은 비상 국면의 안전 의무 | 연속 → 비상, 이후 공개 국면의 안전 의무를 깨지 않을 때만 승인 |
| 명시적으로 미룬 도시 약속 | 그 국면의 공급 후보에서 제외 |

후보 경로는 현재까지 예약한 부하에 후보 부하를 더한 합산 사용량으로 비교한다. 순서는 `허용된 열
등급 → 비상 운전 설비 수 오름차순 → 경로 최소 남은 한도 내림차순 → 작성된 발전 순서 → 규칙
정수 길이 → 구간 수 → 선로 식별자 열의 사전식 순서 → 끝 접속점 식별자`다. 최소 남은 한도는
연속 운전 설비에서는 `연속 한계-사용량`, 비상 운전 설비에서는 `비상 한계-사용량`의 경로 최솟값이다.
따라서 자동급전이 플레이어 몰래 짧고 뜨거운 길을 골라 더 많은 설비를 정지시키지 않는다.

한 수요는 계속 한 발전원·한 경로로 전량 공급하거나 미공급이다. 병렬선에 부하가 자동으로 나뉜다고
암시하지 않는다. 이후 공개 국면의 안전 의무가 보호정지 때문에 깨지는 운영안은 승인할 수 없다.

플레이어 화면은 선택 설비와 병목에만 다음 정도를 펼친다.

```text
현재 사용 2.8 MW · 연속 한계 2.5 MW · 비상 한계 3.0 MW
비상 운전 · 다음 국면 보호정지
```

이 이산 모델만으로 선택이 설명되지 않는다는 사람 증거가 있을 때만 0~100 축열, 형식별 지속시간과
가변 냉각시간을 별도 후보로 검토한다. `실제 도체온도`, `권선 최고온도`, 풍속·일사별 동적 정격을
계산한다고 주장하지 않는다.

### 5.5 시간과 한 개의 공사 능력

열·사고 판정에 쓰는 작성 운영 국면의 순서와 이름은 기반 필수다. 이 절에서 판정할 가설은 별도의
연속 시계가 아니라 **공사기간을 기한과 경쟁시키는가**이다. 시간을 추가 자원으로 만들되 공사 운영
게임으로 확장하지 않는다.

- 동시에 진행하는 공사 묶음은 한 개다.
- 장은 다음 변화까지 남은 결정 경계를 보여준다.
- 현재 창구 안에 끝나지 않는 공사는 발주할 수 없다. 필요하면 도시 약속을 명시적으로 미루고 다음
  공사 창구에서 발주한다.
- 공사 순서를 바꾸는 선택이 있을 때만 기간을 강조한다.
- 기다리기만 하는 버튼과 연속 시계는 만들지 않는다.

모든 공사가 언제나 사건 전에 끝난다면 시간은 핵심 HUD에서 내리고 정보로만 남긴다. 기간을
전략이라고 광고하면서 실제 기한이 없는 현재 상태는 허용하지 않는다.

### 5.6 목표의 세 층

모든 수요를 하나의 이진 성공조건으로 묶지 않는다.

| 층 | 의미 | 실패·결과 |
|---|---|---|
| 안전 의무 | 의료원 생명 유지, 정수장 최소 급수처럼 반드시 지킬 조건 | 지키지 못하면 계획 승인 불가, 원인과 복구 지점 제공 |
| 도시 약속 | 입주 일정, 전체 냉방, 산업 증산처럼 선택 가능한 약속 | 명시적으로 미루고 진행할 수 있으며 해당 장의 도시 상태·결과·에필로그가 달라짐 |
| 운영 기록 | 남은 자금, 최저 여유, 작성된 사고별 공급 유지 결과 | 점수로 합치지 않고 사실로 기록 |

플레이어는 선악을 고르는 것이 아니라 제한된 시간과 자금에서 어떤 약속까지 책임질지 정한다.
별점, 총점과 불투명한 평판 수치는 만들지 않는다. 한 장의 선택 가능한 약속은 최대 한 묶음이다.
미충족 상태에서 운영안을 승인하면 `이번 약속을 미루고 진행`을 직접 확인하고 그 결과를 저장한다.
자동급전 결과만 보고 플레이어가 약속을 포기했다고 추정하지 않는다. `정수장 최소 공급` 같은 안전
의무는 부분공급이 아니라 캠페인 데이터가 정의한 하나의 수요 묶음을 전량 공급한다는 뜻이다.

플레이어는 급전 대상을 직접 선택하지 않는다. 망 구조와 약속 이행 범위를 선택하고, 공급은 화면에
공개된 수요 우선순위와 발전 순서로 결정된다. 같은 등급의 수요가 여럿이면 캠페인 데이터의 표시
순서를 화면에 보여주며 숨은 식별자 순서가 장 성공을 좌우하지 않게 한다.

### 5.7 제한적인 복구

상업 캠페인에서 한 번 완공한 선로를 전혀 고칠 수 없는 것은 지나치게 가혹하다. 범용 그래프
편집기 대신 다음 두 단계만 제공한다.

1. **최근 공사 되돌리기**: 다음 운영안 승인 전까지 마지막 완공 공사 한 건을 취소한다. 명령 기록,
   시각과 자금을 발주 직전 상태로 함께 복원해 여러 슬롯을 소모한 실수를 짧게 고친다.
2. **공사 묶음 철거·교체**: 플레이어가 만든 선로 공사 전체만 선택한다. 부분 구간 편집과 환급은
   없다. 다른 공사가 그 전신주에 의존하면 먼저 종속 공사를 정리하라고 설명한다.

두 번째 기능이 기술적으로 과하면 첫 번째와 촘촘한 결정 경계 체크포인트만 먼저 검증한다. 과거 장
되감기는 여전히 안전망으로 남긴다. 최근 공사 복구·저장·재개는 위치와 자금만이 아니라 운영 국면,
도시 약속, 설비의 이산 열 상태와 보호정지를 같은 명령 재생 결과로 복원해야 한다.

### 5.8 경제

1.0 경제는 두 가지 사실만 소유한다.

- 현재 운영 자금
- 공사비

대출, 이자, 전력 판매수입, 연료비와 시장 가격은 없다. 돈은 “정답을 찾을 시도 횟수”가 아니라
지금 독립성을 살지, 다음 장의 여유를 남길지 판단하게 해야 한다.

안전 의무를 실패했다고 벌금을 소급 청구하지 않는다. 도시 약속은 해당 장의 도시 상태·결과와
에필로그만 바꾸며 다음 장의 수요·사건·기본 지원금을 바꾸지 않는다. 약속을 지키기 위해 쓴 실제
공사비만 이후 자금에 남는다. 각 장의 고정 기본 지원금은 이전 약속과 관계없이 장단점이 다른 안전
의무 해법 둘을 가능하게 해야 한다. 모든 경로를 최적화하는 경제 최적화 도구는 만들지 않는다.

### 5.9 지형

지형은 자유 배치와 노선 선택에 필요한 세 범주만 사용한다.

- 설비 건설 불가: 강물·건물 점유영역·지도 밖
- 선로 횡단 불가: 건물 점유영역·지도 밖
- 건설 가능: 경로 길이에 따라 비용·기간이 늘고, 작성된 위험구역과 겹칠 수 있음

강 위 신규 설비 금지와 선로 횡단 허용은 유지한다. 중심점만 육지인 설비가 수면을 침범하지 않도록
점유영역 전체를 판정한다. 짧은 위험 회랑과 긴 안전 회랑의 차이는 거리 비용·기간과 위험구역
교차만으로 만든다. 도로와 고지대의 별도 공기 보정은 1.0에 넣지 않는다.
위험한 회랑이 비용·시간까지 모두 불리하면 선택이 아니라 함정이므로 짧거나 싼 장점을 가진다.

### 5.10 실제 상태 기반 결과

결과 카드는 두 층으로 나눈다.

1. 사람이 겪은 작성된 결과
2. 규칙 엔진이 계산한 운영 사실

운영 사실은 해당 장과 관련된 것만 한두 문장으로 보여준다.

- 수요 묶음별 공급 여부와 실제 사용 발전원
- 실제 선택 경로와 그 경로의 최소 잔여용량
- 국면별 비상 운전 설비와 보호정지·복귀 결과
- 미공급 수요의 첫 병목과 부족량
- 해당 장의 작성된 사고에서 사용 불가가 된 설비
- 플레이어가 명시적으로 확정한 도시 약속 상태
- 남은 운영 자금

작성된 여러 사고 조건에서 공급을 유지했으면 `각 사고에서도 공급 유지`라고만 쓴다. 실제로 서로
다른 경로가 선택되고 공유 설비·위험구역도 독립이라는 별도 판정이 없으면 `독립 경로`라고 쓰지
않는다. 공급에 성공한 경로에는 `첫 병목` 대신 `경로의 최소 여유`라고 표현한다. 특정 발전원이나
지형을 결과 코드가 특별 취급하지 않는다.

`모두`, `완전히`, `안전하게`는 실제 판정이 그 범위를 증명할 때만 사용한다.

## 6. 캠페인 구조

여덟 임무와 청류시 한 지도는 유지한다. 플레이어 화면에서는 `프롤로그`라는 말을 최소화하고,
첫 두 임무 안에 조작 안내를 녹인다. 세 번째 임무 뒤 `운영 인수 완료 · 6개월 후`로 본편 전환을
분명히 한다.

| 순서 | 제목 | 극적 질문 | 고유한 플레이 동사 | 장에 남는 선택 |
|---|---|---|---|---|
| 1 | 첫 불빛 | 첫 입주 약속을 제때 현실로 만들 수 있는가? | 자유 배치·연결 | 첫 동부 간선과 남은 자금 |
| 2 | 두 번째 심장 | 두 줄이면 정말 두 번 안전한가? | 공간적으로 분리 | 의료원 독립 회랑 |
| 3 | 두 번째 전원 | 발전량이 충분해도 모든 설비가 부하를 견딜 수 있는가? | 정격 감사·시운전 | 남부 전원과 운영권 인수 |
| 4 | 북안의 약속 | 성장 수요를 어디까지 함께 묶을 것인가? | 서비스권역·분기 | 첫 공유용량 부채와 도시 약속 |
| 5 | 누구의 여유인가 | 더운 저녁의 열여유를 누구에게 쓸 것인가? | 열여유 배분 | 보강·별도 회랑·약속 연기 결과 |
| 6 | 물이 닿기 전에 | 필수시설만 먼저 지킬지 도시 약속까지 지킬지 결정할 수 있는가? | 지형 우회 | 실제 재난을 견딘 고지대 망 |
| 7 | 꺼야 지킬 수 있다 | 자기 망을 믿고 핵심 설비 정지를 승인할 수 있는가? | 계획정지 | 피날레 전 정비와 전원 분담 |
| 8 | 가장 긴 밤 | 지금까지 남긴 여유는 누구에게까지 닿는가? | 종합 대응 | 플레이어 고유의 완성망과 에필로그 |

### 6.1 임무별 설계

#### 1. 첫 불빛

- 안내: 자유 배치·자석 맞춤·확대, 소형 변전소의 서비스 권역과 실제 공급 경로, 초안·발주·완공
- 결정: 넓은 합법 부지에서 동부 생활권의 변전소 위치와 첫 간선을 정해 현재 비용과 미래 분기
  여유를 비교
- 지형: 첫 수면 접근에서 `강 위 설비 금지 · 선로 횡단 허용`을 한 번만 직접 보여줌
- 결과 보상: 동부 주거지 창과 도로 조명이 켜짐
- 제한: 실패 비용 없이 최근 공사를 되돌릴 수 있음

#### 2. 두 번째 심장

- 안내: 전기적으로 다른 경로와 공간적으로 다른 회랑의 차이
- 결정: 값싼 두 선을 같은 강변에 자유 배치할지, 한 선을 고지대로 충분히 떨어뜨릴지
- 사건: 실제 침수가 아니라 작성된 `범람 안전 차단시험`
- 결과 보상: 수술실 전환 시험이 중단 없이 끝나며 박지현이 구체적인 현장 결과를 말함

#### 3. 두 번째 전원

- 안내: 일반선·보강선, 발전원·경로·병목, 선로·변압기·접속부의 평상시 연속 한계
- 결정: 남부 전원을 어디에서 합류시키고 어떤 정격과 접속부 여유로 연결할지
- 예고: 캠페인 데이터가 소유한 향후 산업 최대수요를 발주 전에 보여주고, 남부 경로의 최소 여유를
  결과에 기록
- 사건: `서부 주간선 인수 시험`; 기후 클라이맥스를 미리 소비하지 않음
- 막 전환: 단계별 조작 안내가 사라지고 청류시 운영을 공식 인수

#### 4. 북안의 약속

- 안전 의무: 정수장 필수 수요 묶음의 전량 공급
- 도시 약속: 북안 입주 일정
- 결정: 기존 공유 분기, 자유 배치한 새 소형·대형 고지대 변전소, 입주 약속 연기 중 선택
- 공간 판단: 서비스권역, 기존 설비 점유영역과 다음 분기를 놓을 실제 공간을 함께 비교
- 예고: 다음 장 더운 저녁의 산업 증산과 중앙 결절 접속부 열여유를 미리 보여줌

#### 5. 누구의 여유인가

- 안전 의무: 의료원·정수장
- 도시 약속: 산업 야간 증산
- 첫 열 규칙: 더운 저녁에 선로·변압기·전신주 접속부의 연속·비상 한계와 다음 경계 상태를 펼쳐 봄
- 결정: 공유 간선의 비상 열여유 사용, 남부 별도 회랑, 산업 약속 연기
- 결과: 어느 전원이 어떤 수요를 실제 맡았는지, 비상 운전과 다음 국면 보호정지 설비를 기록

#### 6. 물이 닿기 전에

- 시간 압박: 범람 경계 전에 끝낼 수 있는 공사 순서
- 도시 약속: 동부 주거지 공급 유지
- 대표 실패: 범람구역을 다시 쓰는 짧은 강변 보완
- 유효 선택: 필수시설만 기한 안에 지키는 짧고 좁은 고지대 직결선, 또는 도시 약속까지 지키는
  길고 비싼 보강 고지대 간선
- 사건: 처음으로 실제 범람이 일어나고 지도 수위와 도로 통제의 시각 상태가 변함
- 규칙 제한: 새 열 규칙을 가르치지 않고 자유 배치·수면·위험구역 판단에 집중
- 결과: 박지현과 이도윤이 의료·급수 현장의 실제 유지 여부를 각각 짧게 전함

#### 7. 꺼야 지킬 수 있다

- 안전 의무: 정비 중 의료원·정수장 최소 공급
- 결정: 제한된 공사 창구에서 어떤 연계망과 열 병목을 먼저 고칠지
- 사건: 플레이어가 준비를 끝낸 뒤 계획정지를 직접 승인
- 열 판단: 서부 전원을 정비로 뺀 동안 남은 경로가 폭염 비상 한계 안에서 끝까지 버티는지 검토
- 인과: 6장 범람 뒤 점검에서 서부 전원 결함이 확인됨. 폭염 전에 계획정비를 끝내면 8장에서 서부
  전원은 사용 가능하며, 열 한계로 계산되는 선로·변압기·접속부 보호정지와 원인을 섞지 않음
- 예고: 다음 장의 최대수요·폭염 한계와 현재 망에서 비상 운전 뒤 보호정지될 설비를 미리 공개
- 감정: “고장을 당한다”가 아니라 “도시를 지키기 위해 스스로 끈다”는 책임의 전환

#### 8. 가장 긴 밤

- 새 도구와 새 규칙 없음
- 복합사고 전 마지막 공사 창구에서 모든 예고 상태를 미리 검토하고 운영안을 승인
- 실제 사건 시작 뒤 건설을 잠그고 `최대수요 → 폭염으로 열 한계 감소 → 직전 국면 비상 운전 설비의
  보호정지 → 범람`을 연속 재생하며 이산 열 상태를 국면 사이에 이어 감
- 안전 의무: 의료원·정수장
- 운영 기록: 고정 우선순위 뒤 남은 망으로 일반 수요가 어디까지 유지되는지
- 결과: 지킨 곳, 멈춘 곳, 실제 우회 경로와 마지막 열여유를 정확히 보여줌

마지막 임무는 한 번의 복합 검사 버튼이 아니라 이미 배운 망이 몇 개의 상태 변화를 연속해서
견디는 장면이어야 한다. 각 상태는 사고 전에 미리 볼 수 있고 안전 의무를 모두 만족해야 운영안이
승인된다. 실제 사건이 시작된 뒤에는 공사하지 않으며 상태 사이에 새 규칙을 설명하지 않는다.

## 7. 이야기 기획

### 7.1 주제

> 여유는 낭비가 아니라 아직 오지 않은 사고를 위한 책임이다.

악당이나 음모는 필요 없다. 청류시는 전력망보다 빨리 성장했고, 과거의 합리적인 절약이 현재의
취약점이 됐다. 플레이어 역시 모든 경로를 독립시킬 수 없으므로 다음 세대의 부채를 일부 남길 수
있다.

### 7.2 세 막

1. **물려받은 망**: 첫 공급, 병원 이중화, 남부 전원 인수
2. **성장의 청구서**: 북안 입주와 산업 증산이 같은 여유를 요구
3. **믿을 수 있는 망**: 범람, 계획정지와 가장 긴 밤이 플레이어의 선택을 시험

### 7.3 반복 인물

| 인물 | 관점 | 말하는 것 | 변화 |
|---|---|---|---|
| 운영센터장 윤서진 | 일정·예산·시민에게 한 약속 | 날짜, 투자 여력, 약속의 범위 | 일정 중심 관리자에서 계획정지를 책임지는 운영자 |
| 계통운영관 강민호 | 오래된 망의 실제 약점 | 설비, 사용량, 병목과 시험 결과 | 과거 타협을 설명하던 기술자에서 플레이어의 망을 믿는 동료 |
| 의료원 시설책임자 박지현 | 의료행위의 연속성 | 수술실, 중환자실, 전환시험 | 요구자에서 준비의 효과를 증언하는 인물 |
| 재난대응관 이도윤 | 날씨·도로·대피·급수 | 수위, 접근 불가 지역, 급수와 대피 | 예보 전달자에서 도시 전체 결과를 연결하는 인물 |

인물이 조작 방법을 읽지 않는다. 목표 체크 목록은 화면이 소유하고, 이야기 카드는 `사람에게 생긴
변화 → 지금의 긴장 → 결정해야 할 책임`만 전달한다.

인물 변화는 표에만 두지 않고 장면에 배정한다. 강민호의 신뢰 변화는 7장 계획정지 승인에서
완료되고, 이도윤은 피날레의 실제 도시 상태를 보고하며, 박지현은 의료 현장의 결과를 증언한다.
윤서진은 마지막에 일정 중심 관리자에서 도시의 선택을 책임지는 운영자로 변화한 결론을 말한다.

### 7.4 선택의 기억

대화 선택지나 호감도는 만들지 않는다. 결과 문구는 §5.8의 제한된 운영 사실만 사용하고, 장과
관련된 한두 사실만 반영한다. 별도 분기 서사 엔진 없이도 플레이어의 설계가 대사에 남는다.

### 7.5 실패의 극중 의미

`임무 평가`는 실제 재난 발생 버튼이 아니라 **운영안 검토**다.

- 실패: “이 설계로 범람을 맞으면 정수장 공급이 끊깁니다.” 설계 화면으로 돌아간다.
- 성공: 운영안이 승인되고 시간이 사건 경계로 진행된다. 그때 실제 사건과 결과가 재생된다.

이 구분으로 실패 뒤 재시도가 사람의 피해를 없던 일로 만드는 모순을 없앤다.
모든 사건은 `현재 상태에서 공사 → 다음 상태 미리보기 → 안전 의무 검토 → 실제 상태 전환` 순서를
사용한다. 도시 약속만 미룬 상태로 승인할 수 있다.

### 7.6 결말

결말의 주인공은 컷신이 아니라 플레이어가 만든 지도다.

1. 사고 설비가 꺼지고 일부 도시가 어두워진다.
2. 병원과 정수장으로 남은 실제 공급 경로가 강조된다.
3. `지킨 곳 / 멈춘 곳 / 남은 여유`를 사실대로 보여준다.
4. 이도윤이 의료·급수·주거·산업의 실제 도시 상태를 보고한다.
5. 박지현이 의료 현장의 결과를 증언한다.
6. 윤서진이 이번 선택을 책임지는 결론을 말한다.
7. 첫 임무의 동부 연결선과 현재 전체 망을 함께 강조하고, 화면을 계속 둘러볼 수 있게 한다.

고정 결말은 하나지만 사실 문장은 현재 상태에 맞게 바뀐다. 모든 수요가 유지됐을 때만 “도시
전체를 지켰다”고 말한다.

## 8. 한국어와 정보 설계

### 8.1 문장 역할 분리

- 이야기 카드: 사람과 상황
- 목표 목록: 성공에 필요한 조건
- 작업 패널: 수치, 병목과 다음 조작
- 지도: 위치, 경로와 상태 변화

같은 목표를 네 곳에서 반복하지 않는다.

### 8.2 인물별 문체

- 윤서진은 일정과 약속을 짧고 단정하게 말한다.
- 강민호는 숫자와 원인을 정확하게 말하되 감정적 결론을 대신하지 않는다.
- 박지현은 MW가 아니라 수술실·중환자실·전환시험을 말한다.
- 이도윤은 해법이 아니라 수위·대피·도로·급수 상황을 말한다.

### 8.3 금지 표현

- `필요한 전력`, `안정적으로`, `계속 운영`만 반복하는 추상 문장
- 판정으로 증명되지 않은 `모두`, `완전히`, `안전하게`
- 내부 ID, enum, 영어 상태명과 원시 예외
- 플레이어가 직접 제어하지 않은 급전을 의도한 선택처럼 서술하는 문장
- 한 수요를 여러 경로로 분할할 수 있다고 오해하게 하는 문장
- 목재·콘크리트 기둥 자체가 뜨거워진다는 `전신주 과열`; `전신주 접속부 열여유`라고 씀
- 실제 온도를 계산하지 않으면서 쓰는 섭씨 숫자, `실시간 열해석`, `실제 동적 정격`

열 정보의 사용자 용어는 네 가지로 제한한다.

| 규칙 값 | 화면 용어 |
|---|---|
| 계속 사용 가능한 한도 | `연속 한계` |
| 짧은 비상 국면의 절대 상한 | `비상 한계` |
| 현재 사용과 연속·비상 한계 사이의 남은 용량 | `열여유` |
| 다음 국면부터 사용 불가 | `보호정지` |

### 8.4 첫 브리핑 톤 예시

> **첫 입주가 오늘 저녁 시작됩니다**
> 동부 생활권에는 아직 배전 변전소가 없습니다. 해가 지기 전 변전소를 세우고 첫 전기를
> 넣어야 합니다. 오늘 만든 길은 앞으로도 이 도시에 남습니다.

목표 목록은 별도로 짧게 쓴다.

> 동부 주거지에 0.8 MW를 공급하세요.

## 9. 화면과 조작

### 9.1 기본 화면 위계

1. 상단: 장 이름, 다음 결정 경계, 운영 자금, 필수 공급 상태
2. 중앙 지도: 도시와 실제 망
3. 오른쪽 상단: 안전 의무와 도시 약속 체크 목록
4. 오른쪽 본문: 선택 대상의 경로·사용량·열여유·병목
5. 오른쪽 하단 고정 영역: 현재 도구와 지금 가능한 행동

`평상시 / 예고 상황` 전환은 부가 기능이 아니라 핵심 조작으로 승격한다. 전환할 때 사용불가 설비,
실제 경로와 지킨 의무가 동시에 바뀌어야 한다.

### 9.2 공사 전 비교

발주 확인은 다음 정보를 한 덩어리로 보여준다.

```text
공사명과 선종
비용 · 완공 예정 경계
표시 구간 길이 · 점유 외곽선 · 배치 판정
접속 수 변화
평상시 공급 변화
예고 상황 공급 변화
국면별 최소 남은 한도 · 보호정지 예상
새 첫 병목 또는 해결된 병목
```

### 9.3 도구 노출

현재 임무에서 쓸 이유가 없는 도구는 숨긴다. 화면에 노출한 모든 변전소·선로 도구는 캠페인에서
최소 두 번 의미 있는 선택으로 사용되어야 한다. 그렇지 않으면 해당 도구를 제거하거나 콘텐츠를
다시 설계한다.

건설 도구를 고르면 수면·건물·점유영역만 낮은 대비로 드러내고, 현재 구간의 최대 거리,
자석 맞춤 대상과 확정될 접속 수를 표시한다. 초안점은 끌어서 옮기고 `Backspace` 또는 우클릭으로
마지막 점을 되돌리며 `Esc`로 전체 초안을 취소한다. 열 정보는 항상 지도를 덮지 않고 선택 설비,
경로 감사와 별도 `열여유 보기`에서만 펼친다.

### 9.4 카메라

자유 배치에서는 확대·이동이 필수다. 그러나 연속 카메라 시스템으로 확장하지 않는다.

- `전체 보기 / 1.5배 / 2.25배` 세 단계만 사용한다.
- 휠 또는 `+ / -`로 포인터·키보드 커서를 중심으로 확대한다.
- 가운데 버튼 또는 `Space+드래그`로 지도만 이동하고 `Home`으로 전체 보기에 복귀한다.
- 키보드 커서가 화면 가장자리의 안전 여백에 닿으면 지도가 같은 방향으로 따라간다.
- 접속점 맞춤 반경, 선 굵기와 선택 외곽선은 줌과 무관한 화면 크기를 유지한다.
- 전체 보기에는 핵심 시설명만, 확대 화면에는 전신주·점유영역·세부 수치를 보여준다.

연속 줌, 회전, 관성 이동과 미니맵은 만들지 않는다.

## 10. 시각 방향

목표는 “업무용 계통도와 살아 있는 도시 지도의 중간”이다. 평상시에는 건설 격자와 좌표를 감추고
도시와 망의 형태가 먼저 보여야 한다. 장식이 규칙을 가리지 않되 선과 텍스트만 남아 내부 도구처럼
보여서도 안 된다.

### 10.1 도시가 반응하는 최소 연출

- 주거지 창과 가로등의 점등·소등
- 의료원 수술실 표식과 비상 전환 상태
- 정수장 펌프와 급수 상태
- 산업단지 조업·안전 정지 상태
- 사건 중 강 수위, 통제 도로와 정비구역

각 시설은 두세 상태의 짧은 반복 애니메이션만 가진다. 사람 군중, 차량 시뮬레이션과 복잡한
파티클은 만들지 않는다.

### 10.2 장별 색과 날씨

- 첫 저녁: 따뜻한 주거 조명
- 인수 시험: 맑은 낮과 기술 점검 표식
- 야간 증산: 공장 조명과 차가운 밤색
- 범람 예보: 흐린 하늘, 높아지는 강과 통제선
- 계획정지: 정비 표식과 부분 소등
- 가장 긴 밤: 폭염 잔광, 폭우와 남은 우회 경로 강조

### 10.3 설비 표현

모든 설비는 실루엣, 상태 패턴, 연결점과 선택 외곽선이 같은 규칙을 사용한다. 통전선의 흐름은
느리고 절제되게 표현하며, `현재 미사용`을 단절처럼 보이게 하지 않는다. 공급 실패 때는 전체
경로를 과도한 붉은 화면으로 덮지 않고 첫 병목과 영향 수요를 연결한다.

열 상태는 색만으로 구분하지 않는다.

- 연속 운전: 기존 실선과 작은 열여유 막대
- 비상 운전: 호박색 이중선·열 아이콘·`비상 운전` 문장
- 보호정지 예정: 다음 경계 표식과 정지할 국면 이름
- 보호정지: 사선 패턴, 열린 연결 표식과 복귀 예상 경계

움직임 줄이기에서는 통전 흐름과 열 아지랑이를 정지 패턴으로 바꾼다.

### 10.4 인물

네 인물은 작은 고정 초상과 일관된 카드 색만 가진다. 립싱크, 다수 표정과 컷신은 제외한다.

## 11. 사운드

사운드 목표는 많은 곡이 아니라 상태의 감정적 무게다.

- 도시 환경음 한 묶음: 바람, 먼 교통, 낮은 변압기음
- 장별 날씨 층: 비, 강풍, 야간 산업음
- 공사 발주, 완공, 통전, 차단, 경고, 결과 확인 효과음
- 첫 점등과 마지막 우회 성공에만 짧은 음악적 모티프

소리는 화면 정보를 보강하고 필수 상태를 단독으로 전달하지 않는다. 음성, 긴 음악 앨범과 동적
믹싱 시스템은 제외한다. 실제 제품 후보에서는 코드 생성 임시음이 아니라 출처와 재배포 권리가
명확한 최종 자산을 사용한다.

## 12. 온보딩과 난이도

### 12.1 안내의 감소

- 1장: 자유 배치, 자석 맞춤, 확대·이동, 초안점 이동과 수면 거부를 직접 안내하고 실패 비용을 없앤다.
- 2장: 선 교차와 실제 접속, 공간적으로 다른 두 회랑을 스스로 만든다.
- 3장: 선로·변압기·접속부의 사용량과 연속 한계를 읽는다. 아직 비상 열 상태는 쓰지 않는다.
- 4장: 서비스권역과 미래 분기 공간을 자유 배치로 판단한다.
- 5장: 연속·비상 한계, 비상 운전과 다음 경계 보호정지를 한 번에 가르친다.
- 6장 이후: 새 건설·열 규칙 설명 없이 목표·예고·현재 망만 제공한다.

### 12.2 난이도는 숫자가 아니라 질문으로 상승한다

```text
연결 여부
→ 경로 독립성
→ 경로 전체 연속 한계
→ 서비스권역·공유 접속부와 미래 공간
→ 비상 열여유와 도시 약속
→ 지형과 기한
→ 계획정지 중 남은 경로 열여유
→ 열·보호정지·범람의 연속 대응
```

수요 숫자만 키워 난이도를 올리지 않는다.

### 12.3 유효 해법

각 본편 장에는 장단점이 다른 설계 원형이 최소 두 개 있어야 한다. 모든 면에서 싼·빠른·안전한
하나의 해법이 있으면 다른 선택은 장식이다. 검사기는 전체 해법을 탐색하지 않되, 제작자가 의도한
두 원형과 대표 실패를 증명한다.

## 13. 재플레이와 출시 콘텐츠

절차 생성과 무한 샌드박스 대신 작은 작성 콘텐츠를 재사용한다.

### 13.1 캠페인 재도전

- 도시 약속을 모두 지키는 설계
- 더 적은 비용으로 안전 의무만 지키는 설계
- 강변 회랑 의존을 최소화한 설계

캠페인 완료 뒤 장 시작 상태를 골라 다시 설계할 수 있다. 종합 점수 대신 각 장의 사실 기록을
비교한다.

### 13.2 후일담 계약

전체 캠페인의 핵심 순환이 사람 관찰에서 재미있고 다른 설계를 다시 시험하고 싶다는 요구가
확인될 때만 최대 세 개를 검토한다. 목표 시간을 채우기 위해 추가하지 않는다.

- 제한된 공사비로 같은 안전 의무 지키기
- 강변 설비 없이 범람 대응하기
- 한 발전원 정지 중 도시 약속까지 유지하기

기존 지도·수요·사건과 평가기를 재사용한다. 두 번째 도시와 새 시스템은 만들지 않는다.

### 13.3 데모

데모는 첫 불빛만 보여주거나 다섯 장을 그대로 길게 재생하지 않는다.

1. `첫 불빛`의 무벌점 자유 배치로 변전소·선로, 자석 맞춤과 수면 규칙을 익힌다.
2. `몇 해 뒤`의 작성된 전환으로 4장 완료 상태의 `누구의 여유인가` 핵심 구간을 연다.
3. 짧은 공유 회랑의 비상 운전·다음 국면 보호정지와 긴 별도 회랑을 비교한다.
4. 산업 약속을 지키거나 미루는 선택과 실제 결과를 본 직후 끝낸다.

그래야 이 게임의 고유한 재미인 `자유 배치 → 사고·열 미리보기 → 책임 있는 선택 → 실제 도시
결과`가 한 번씩 드러난다. 데모 전용 규칙이나 별도 결말은 만들지 않고 상용 핵심 구간을 재사용한다.

## 14. 접근성과 사용성

- 모든 상태를 색과 함께 선 모양·패턴·아이콘·문장으로 표현한다.
- 키보드 자유 커서는 방향키로 작은 세계 거리, `Shift+방향키`로 큰 거리를 이동한다.
- 접근성 설명은 원시 좌표 대신 가까운 시설과 방향·거리, 배치 가능 여부와 이유를 말한다.
- `Q / E`로 가까운 접속 후보를 순환하고 `Enter`로 확정하며 `+ / -`, `Home`으로 카메라를 제어한다.
- `Tab / Shift+Tab`은 표준 UI 초점 이동으로 보존한다. `Esc`는 초안이 있으면 먼저 취소하고, 없으면
  일시정지 메뉴를 연다.
- 수요별 경로는 색 외에 굵기와 방향 표식으로 강조한다.
- 비상 운전과 보호정지는 색 외에 이중선·사선·아이콘·문장으로 구분한다.
- 화면 배율 100%·125%를 지원하고 1280×720에서 핵심 행동이 스크롤 밖에 숨지 않는다.
- 텍스트 속도에 의존하는 연출과 반복 섬광을 사용하지 않는다.
- 필수 정보를 소리만으로 전달하지 않는다.
- 버튼 재배치가 일어나도 현재 맵 초점을 빼앗지 않는다.
- 전체 키 재설정과 게임패드는 첫 출시의 필수 범위가 아니지만, 표준 키와 도움말은 한 화면에서
  확인할 수 있어야 한다.

## 15. 사람 검증 계획

자동검사와 LLM은 재미와 제품 가치를 승인하지 않는다. 사람 관찰은 세 번만 크게 수행한다.

### 15.1 상용 핵심 구간

`누구의 여유인가`를 4장 완료 상태에서 시작하는 독립 구간으로 만들고 최종 수준의 지도·문체·사운드·
결과까지 완성한다. 자유 배치와 열 규칙의 결정론적 검사가 먼저 통과한 뒤, 처음 보는 한국어
플레이어에게 단계 B의 무벌점 자유 배치 흐름과 `고정망에서 연속 한계 읽기`를 짧은 사전 구간으로
먼저 제공한다. 그 뒤 다음을 수행하고 자기 말로 설명할 수 있어야 한다. 새 1~4장 전체 콘텐츠를
선제 제작해 테스트하는 것은 아니다.

- 기존 필수시설 경로와 첫 병목을 읽는다.
- 보이는 격자 없이 원하는 회랑에 설비를 놓고 자석 맞춤·확대·이동을 사용한다.
- 수면 위 설비는 금지되지만 선로 횡단은 허용됨을 예측한다.
- 공사 초안의 평상시·예고 상황 효과를 비교한다.
- 전신주 기둥이 아니라 접속부에 열 한계가 있음을 설명한다.
- 연속 한계, 비상 한계와 다음 국면 보호정지를 자기 말로 예측한다.
- 결정 경계 안에서 끝나는 공사를 고른다.
- 산업 증산 약속을 지켜 열여유를 쓸지, 명시적으로 미루고 다음 국면 여유를 남길지 결정한다.
- 최근 공사를 되돌려 다른 유효 설계를 시험한다.
- 결과 카드에서 실제 공급원·경로·비상 운전·보호정지와 약속 상태를 확인한다.

### 15.2 전체 캠페인

다음만 기록한다.

- 각 장에서 플레이어가 실제로 고민한 선택
- 설명 없이 막힌 지점과 오래 반복한 조작
- 장별 기억에 남은 질문과 사람 결과
- 재시작·되감기 이유
- 첫 완주 시간과 중단 이유

통계적 성공률로 포장하지 않는다. 반복되는 major 혼란만 수정한다.

### 15.3 실제 패키지 후보

설치, 첫 실행, 저장·재개, 설정, 마지막 에필로그와 종료까지 확인한다. 한국어 전문 교정자는 별도로
전체 문구를 한 번 읽는다. LLM 플레이를 사람 검증이나 공개 출시 근거로 합산하지 않는다.

## 16. 제작 단계

### 단계 A — 제품 정의 고정

- 이 문서의 장르·길이·핵심 약속·제외 범위를 승인한다.
- 현재 내부 후보를 기술 기준선으로 재분류한다.
- 새 규칙과 저장 버전의 구현 범위를 별도 범위 계약으로 고정한다.

### 단계 B — 자유 좌표 기반

- 새 고정소수점 좌표, 거리 반올림, 점유영역, 수면·건물·교차 판정을 먼저 고정한다.
- 첫 불빛의 작은 건설 흐름으로 자유 배치, 자석 맞춤, 세 단계 카메라와 마우스·키보드 동등성을 닫는다.
- 대표 확인은 같은 입력의 같은 좌표·비용, 줌 불변, 수면 경계 설비 거부·선로 횡단 허용, 제3 설비
  관통·공선 겹침 거부와 교차 비접속으로 제한한다.
- 이 단계에서는 기존 고정 용량 한계만 사용하며 열 상태와 전체 캠페인을 섞지 않는다.

### 단계 C — 열 국면 기반

- 작성된 고정망에서 선로·변압기·전신주 접속부의 연속·비상 한계, 한 국면 비상 운전, 다음 국면
  보호정지와 한 국면 냉각 뒤 복귀를 검증한다.
- 열을 고려한 결정론적 경로 선택과 모든 공개 국면 연속 미리보기를 닫는다.
- 대표 확인은 연속·비상 경계값, 공유 접속부 합산, 비상 사용 권한, 보호정지·복귀와 긴 연속 경로가
  짧은 비상 경로보다 먼저 선택되는 사례로 제한한다.
- 실제 온도, 실시간 급전과 캠페인 시청각 마감은 열지 않는다.

### 단계 D — 상용 핵심 구간

- `누구의 여유인가` 한 장만 4장 완료 상태에서 시작하는 독립 구간으로 재제작한다.
- 자유 배치, 열 미리보기, 경로 감사, 결정 경계, 안전 의무·도시 약속과 최근 공사 복구를 통합한다.
- 최종에 가까운 지도, 인물 문체, 환경음과 통전·보호정지 보상을 적용한다.
- 사람 관찰에서 이산 열 판단도 불투명하면 0~100 수치나 공식을 더하지 않고 화면 표현을 `상태별
  현재 허용량` 중심으로 줄인다. 연속·비상·보호정지·복귀의 이산 상태 전이는 유지한다. 공사기간과
  기한의 경쟁이나 도시 약속이 의미 있는 선택을 만들지 못하면 해당 가설만 제거한다.
- 채택한 열 모델 하나로 §3·5·6·8·12·17과 5·7·8장 문구를 통일한 뒤에만 단계 E로 넘어간다.
- 핵심 재미가 성립하지 않으면 전체 캠페인 제작을 멈춘다.

### 단계 E — 첫 네 장과 공통 UX

- 첫 세 임무의 안내 감소 곡선과 `운영 인수` 막 전환을 완성한다.
- 4장에서 서비스권역·미래 분기 공간을 쓰고 5장의 열 위기를 예고한다.
- 단계 D에서 유지하기로 한 공사 기한·도시 약속과 결과 기록, 저장·복구, 한국어 표현만 공통화한다.

### 단계 F — 후반 캠페인 제작

- 단계 D의 5장을 본편에 통합하고 6~8장을 각기 다른 극적 질문과 플레이 동사로 제작한다.
- 장마다 유효 설계 원형 두 개, 대표 실패와 복구를 확인한다.
- 5장 뒤 새 건설·열 규칙을 추가하지 않는다.

### 단계 G — 시청각·접근성 마감

- 도시 반응, 장별 날씨, 인물 초상, 최종 사운드와 에필로그를 완성한다.
- 두 해상도·두 화면 배율, 마우스·키보드, 저장·재개를 확인한다.

### 단계 H — 사람 대상 시험과 공개 후보

- 전체 캠페인 사람 관찰과 한국어 전문 교정을 닫는다.
- 실제 지원 환경, 서명·공증, 라이선스·크레딧과 상점 설명을 확정한다.
- 새 설치에서 전체 완주한 실행물과 바이트가 동일한 공개 후보를 만든다.

## 17. 1.0 범위

### 기반 필수

- 직접 만드는 분기·합류 배전망
- 보이는 격자 없는 고정소수점 자유 배치, 점유영역·지형 판정과 세 단계 카메라
- 설비별 사용량·접속 여유와 선로·변압기·전신주 접속부의 연속·비상 열 한계
- 작성된 국면 사이 이산 열 상태, 보호정지·한 국면 냉각과 전체 공개 국면 미리보기
- 수요별 공급원·전체 경로·용량 및 열의 첫 병목 강조
- 평상시와 예고 상황 비교
- 발주 전 가상 완공 효과
- 최근 공사 복구 또는 동등한 촘촘한 체크포인트
- 실제 망 상태를 반영한 결과와 에필로그
- 여덟 임무의 완결 캠페인
- 저장·재개·설정·접근성·설치 가능한 서명 후보

### 상용 핵심 구간에서 판정할 가설

- 공사기간과 기한의 경쟁, 한 개의 공사 능력
- 안전 의무·도시 약속·운영 기록

두 가설은 제품 방향의 우선안이지만 단계 D의 사람 관찰 전에 구현 전역의 필수 구조로 고정하지
않는다. 의미 있는 선택을 만들지 못하면 더 복잡하게 보완하지 않고 축소하거나 제거한다.

### 조건부

- 플레이어 공사 묶음의 전체 철거·교체
- 0~100 축열, 형식별 비상 지속시간과 가변 냉각시간
- 후일담 계약 최대 세 개

상용 핵심 구간과 사람 관찰에서 필요성이 확인될 때만 연다.

### 제외

- 전력시장, 대출, 연료경제, 발전 기술 수집과 기술 트리
- 여러 공사반, 자재 재고와 인력 시뮬레이션

- 실제 섭씨온도·풍속·일사별 동적 정격, 설비 열화·화재·확률 고장
- 수동 급전·차단기·재폐로, 수리반과 열 관리 전용 인력
- 곡선 선로, 자동 전신주, 도로 추종과 완공망의 임의 중간 접속점 삽입

- 이 장의 극적 질문을 한 문장으로 말할 수 있는가?
- 이전 장과 다른 플레이 동사가 있는가?
- 장단점이 다른 유효 설계 원형이 두 개 이상 있는가?
- 한 선택이 비용·기간·신뢰도·미래 가치 모두에서 우월하지 않은가?
- 자유 배치가 숨은 픽셀 최적화 없이 실제로 다른 회랑을 만들게 하는가?
- 물·건물·점유영역과 선로 횡단 규칙을 초안에서 예측할 수 있는가?
- 연속·비상 한계와 다음 국면 열 상태가 별도 설명 없이 비교 가능한가?
- 짧은 뜨거운 경로 대신 긴 차가운 경로가 선택된 이유를 화면이 설명하는가?
- 플레이어가 발주 전에 어느 약속과 사고 결과가 바뀌는지 예측할 수 있는가?
- 실패했을 때 어느 설비와 결정이 원인인지 설명할 수 있는가?
- 한 번의 실수가 오래된 진행 전체를 폐기하게 만들지 않는가?
- 결과가 실제 발전원·경로·공급 상태만 말하는가?
- 인물의 문장이 목표 목록을 그대로 읽지 않는가?
- 장이 끝났을 때 도시의 모습과 사람의 상태가 하나 이상 달라지는가?
- 피날레의 망이 플레이어의 앞선 선택에 따라 눈에 띄게 다른가?

하나라도 답하지 못하면 콘텐츠를 만들기 전에 장 설계를 다시 쓴다.

이 제안을 채택하면 다음 충돌을 의식적으로 해소해야 한다.

|---|---|

| 33×21 정수 셀·격자 커서·고정 카메라 | 고정소수점 자유 좌표, 점유영역, 자석 맞춤과 세 단계 카메라 |
| 선로·변전소·전신주의 고정 정격 | 연속·비상 한계와 국면별 열 상태·보호정지·냉각 |
| 정수 셀 거리와 현재 경로 순서 | 고정소수점 세계좌표의 정수 길이와 열 안전 우선 경로 순서 |
| 모든 정상 목표가 사실상 필수 전량 공급 | 안전 의무와 선택 가능한 도시 약속을 분리 |
| 공사기간에 실질 기한 경쟁이 없음 | 작성된 결정 경계와 연결하거나 핵심 약속에서 제거 |
| 완공 자산 복구는 장·과거 장 재시작뿐 | 최근 공사 복구를 필수로, 묶음 철거는 조건부로 검토 |
| 결과 문구가 고정 한 벌 | 실제 망에서 허용된 운영 사실만 파생해 제한 변형 |
| 프롤로그에서 실제 침수·열돔을 먼저 사용 | 안전시험·인수시험으로 재톤하고 재난은 본편에 집중 |
| 도로는 시각 장식 | 1.0에서는 시각 연출로 유지하고 별도 회랑 규칙을 열지 않음 |
| 현재 출시 저장 v2가 콘텐츠 해시에 결합 | 새 캠페인은 새 저장·콘텐츠 버전, 옛 저장은 `.bak` 보존 |
| 현재 내부 후보를 출시 마감 단계로 표현 | 기술 내부 후보와 상업 제품 승인 상태를 분리해 표기 |

현재 `GAME_DESIGN_KO.md`, `ROADMAP_2D.md`와 `RELEASE_REBUILD.md`는 이 제안이 채택되기 전까지 기존
제품과 구현 권위를 유지한다. 이 문서는 그 문서들을 몰래 덮어쓰지 않는다.

## 21. 다음 결정

다음 구현을 시작하기 전에 소유자가 먼저 선택해야 할 것은 기능 목록이 아니다.

1. Gridworks를 한 도시의 2.5~4시간 소형 프리미엄 전략 게임으로 고정할 것인가?
2. 셀 배치를 버리고 결정론적 자유 좌표·점유영역·세 단계 카메라를 새 공간 기반으로 채택할 것인가?
3. 세 설비군의 연속·비상 열 한계와 국면 사이 열 상태를 핵심 운영 규칙으로 채택할 것인가?
4. `안전 의무 / 도시 약속 / 운영 기록`의 세 층을 상용 핵심 구간에서 검증할 우선 가설로 채택할 것인가?
5. `누구의 여유인가` 한 장을 상용 핵심 구간으로 다시 만든 뒤 전체 제작 여부를 판단할 것인가?
6. 현재 내부 후보를 상업 출시 후보가 아니라 기술 기준선으로 재분류할 것인가?

권장 답은 여섯 항목 모두 **예**다. 이 결정 없이 현재 후보를 계속 다듬으면 화면과 문장은 나아져도
“왜 다음 장을 플레이해야 하는가”라는 가장 큰 질문은 남는다.
