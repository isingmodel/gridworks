# 개발자 직접 플레이 파일럿 v1

이 기록은 공식 cold actor 증거가 아니다. `e6682e6fd3e7d00f263673338dc039faaf4103e1`의
기본 `CommercialMain.tscn`을 1920×1080, UI 100%, fresh storage에서 Computer Use의 실제 마우스
입력으로 플레이한 개발자 관찰이다. LLM judge 점수나 사람 증거로 세지 않는다.

## 실행한 흐름

1. 타이틀에서 새 게임을 시작했다.
2. 자동으로 열린 전체 조작 도움말을 닫았다.
3. 첫 불빛에서 변전소를 배치·발주·완공했다.
4. 서부 발전 접속점에서 새 변전소까지 간선을 놓고 발주·완공했다.
5. 변전소에서 동부 생활권까지 인입선을 놓고 발주·완공했다.
6. `필수 공급 1/1 ✓`를 확인하고 첫 경계를 승인했다.
7. 같은 프로세스에서 저장하고 제목으로 돌아온 뒤 `이어하기`를 눌렀고, 별도 fresh process에서도
   같은 저장을 다시 열어 재개 첫 화면을 비교했다.

## 재현한 UX 결함

- 새 게임은 임무 briefing보다 전체 조작 도움말을 먼저 덮어쓴다. 도움말을 닫은 뒤에도 첫 목표와
  다음 행동이 고정 영역에 보이지 않고 작은 inspector 안에서 사실상 사라진다.
- 공급 가능 상태는 상단 `필수 공급 1/1 ✓`로만 간접 확인된다. 왜 승인 가능한지와 승인 뒤 무엇이
  일어나는지를 읽을 고정 문장이 없다.
- 승인과 최근 공사 복구가 같은 작은 row에 인접해 있어 파일럿에서 복구를 승인으로 오인했고,
  완공한 인입선을 한 번 되돌렸다. 복구 가능했지만 행동 위계와 파괴 행동 구분이 약하다.
- 첫 불빛 성공 직후 제목은 `첫 불빛 · 결과`지만 화면의 권위 상태는 이미 다음 장으로 넘어간다.
  상단 현금은 다음 장 지원금이 반영된 `6,908,000원`, 경계는 `북안 회랑 차단시험`, 우측 카드는
  `북안 A · 차단시험 0 kW ×`와 `강변 B · 차단시험 0 kW ×`, 지도도 다음 장 시설을 표시했다.
  완료 장의 성공과 다음 장의 미완료 상태가 한 화면에서 정면으로 충돌한다.
- 같은 프로세스의 `이어하기`는 직전 결과 timeline과 다음 장 상태가 남은 채 generic 조작 도움말을
  열었다. fresh process에서는 transient 결과가 사라져 현재 목표를 되찾기 어려웠다. 저장 schema를
  늘리지 않아도 Core의 `ChapterResults`와 현재 snapshot으로 직전 결과·현재 장·다음 행동을 다시
  구성할 수 있다.

다음 제품 후보는 결과 presentation을 완료 직전 snapshot으로 동결하고, 명시적 `다음 임무` 전환
전까지 공사·승인·복구 입력과 다음 장 projection을 잠가야 한다. briefing·window story·operations·
result·epilogue·resume orientation을 서로 다른 presentation mode로 표현하는 것이 우선 수정이다.

## Gate C 후보 반영 상태 — 2026-08-23

후속 후보는 위 관찰을 다음처럼 반영했다. 이 절은 공식 cold actor나 점수가 아니라, 원 관찰과 수정
방향을 연결하는 개발 기록이다.

- 새 게임은 generic 도움말 대신 잠긴 `Briefing`을 먼저 열고, 목표·다음 행동·주 행동을 고정한다.
- 첫 불빛의 다음 행동은 실제 완공 그래프에 따라 변전소 배치 → 발전원 연결 → 생활권 인입 →
  `필수 공급 1/1 ✓` 확인·승인 순서로 바뀐다.
- `Result`는 승인 직전의 Core·공사·현금·열·지도 상태를 동결하고 다음 장 projection과 공사·복구
  입력을 숨긴다. `다음 임무`를 누른 뒤에만 별도 다음 장 `Briefing`을 연다.
- `Continue`는 직전 결과, 현재 장·경계·목표, 현재 현금·공사시각과 다음 행동을 한 카드에 재구성한
  `ResumeOrientation`을 열며, 진행 재개 전 저장된 draft를 취소하지 않는다.
- UI 100%·125% 창 모드 smoke에서 briefing·operations·result·resume 캡처와 실제 입력 전이를
  통과했다. macOS 화면 잠금 때문에 이 후보의 두 번째 Computer Use 직접 조작은 아직 공식 평가 전에
  다시 실행해야 한다.
