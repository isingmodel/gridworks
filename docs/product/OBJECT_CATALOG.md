# Gridworks — 오브젝트 카탈로그

이 문서는 플레이어가 보는 오브젝트의 의미와 상용 v2에서 가능한 동작을 정리한다. 정확한 수치와
식별자는 [상용 구현 계약의 단일 권위](../scopes/COMMERCIAL_2D_IMPLEMENTATION.md#2-단일-권위와-동결-경계),
현재 구현 권한은 루트 [README](../../README.md)가 소유한다.

## 상태 표기

- `구현됨(기본 v2)`: 현재 기본 `CommercialMain`과 상용 v2 Core에서 사용할 수 있음
- `계획·미개방`: 단계 H 또는 별도 후속 범위의 계획이며 현재 구현 권한이 없음
- `회귀 전용`: 과거 장면에만 남아 있고 상용 v2 능력으로 세지 않음
- `제외`: 1.0에서 만들지 않음

## 현재 경계

상용 v2 단계 G 내부 후보는 보이는 격자 없는 고정소수점 자유 좌표에 전신주·변전소를 배치한다. 원형
점유영역이 지도 밖, 수면·건물 또는 기존·초안 설비에 닿으면 발주 전에 거부한다. 위험구역 노출은
경고와 작성 사건 판정에 이어진다. 선로는 강을 건널 수 있지만 새 지지 설비는 물 위에 세울 수 없다.

한 선로 공사는 순서 있는 한 경로지만, 완공 접속점을 다음 공사의 시작·끝으로 다시 써서 전체
망에서 분기·합류한다. 선로 도체·변전소 주기기·전신주 접속부는 현재 사용량과 연속·비상 열 한계,
다음 국면 보호정지와 한 국면 냉각 뒤 복귀를 가진다. 이 기반은 같은 망을 이어 쓰는 여덟 임무,
안전 의무·도시 약속·공사 기한과 결과·에필로그까지 연결됐다. 최종 날씨·초상·audio cue,
settings v3·움직임 줄이기와 내부 macOS package도 단계 G에서 연결했다.

## 전력회사 설비

| 오브젝트 | 상태 | 플레이어 동작 | 상용 v2 규칙 | 제외 |
|---|---|---|---|---|
| 발전 접속점 | 구현됨(기본 v2) | 선로를 연결하고 공급 상태 확인 | 출력 한도, 작성 순서, 국면별 사용량 | 발전기 세부 운전·연료조달 |
| 일반 전신주 | 구현됨(기본 v2) | 자유 좌표에서 경유점 지정, 완공 뒤 분기 시작 | 최대 3개 구간, 접속부 연속·비상 한계 | 장력·풍하중·재고 |
| 보강 전신주 | 구현됨(기본 v2) | 큰 분기·합류 지점에 선택 | 최대 4개 구간, 더 큰 접속부 열 한계와 비용 | 사용자 지정 하드웨어 |
| 일반 배전선 | 구현됨(기본 v2) | 두 접속점 사이 자유 경로 계획·발주 | 최대 경간, 도체 연속·비상 한계, 공간 위험 | 상불평형·상세 도체 사양 |
| 보강 배전선 | 구현됨(기본 v2) | 공유 주간선·우회선에 선택 | 더 큰 도체 열 한계와 비용 | 실제 온도·연속 축열 |
| 소형 배전 변전소 | 구현됨(기본 v2) | 수면·건물·설비를 피해 자유 배치 | 접속 수, 서비스 권역, 주기기 연속·비상 한계 | 탭·무효전력·보호계전 |
| 대형 배전 변전소 | 구현됨(기본 v2) | 병원·산업지대 결절에 선택 | 더 많은 접속, 큰 주기기 열 한계와 비용 | 베이 상세 설계·증설 공사 |
| 선로 공사 | 구현됨(기본 v2) | 완공 접속점에서 시작해 초안 전신주를 옮기고 다른 접속점에서 종료 | 한 경로의 원자 시운전 | 한 공사 안의 나무형 편집 |

### 연결 수와 열 한계

`연결 3/4`는 물리적으로 더 연결할 수 있는 선로 구간 수다. `현재 사용 2.0 / 연속 2.5 /
비상 3.2 MW`는 현재 국면의 사용량과 두 열 한계다. 둘은 서로 다른 값이며 UI도 따로 보여준다.
전신주에서 말하는 열 한계는 기둥 온도가 아니라 단자·퓨즈·개폐기·분기 접속 장치 조합의 계획
한계다.

## 수요처와 비전력회사 설비

| 오브젝트 | 상태 | 의미 | 공급·사건 규칙 |
|---|---|---|---|
| 주거지 | 구현됨(기본 v2) | 일반 주거·상업 수요 | 장마다 작성된 수요와 안전 의무·도시 약속 |
| 청류의료원 | 구현됨(기본 v2) | 가장 높은 우선순위의 생명 유지 전력 | 두 접속 회선과 범람 차단시험 중 공급 gate |
| 정수장 | 구현됨(기본 v2) | 도시 필수 서비스 | 작성 국면의 필수 공급과 결과 사실 |
| 산업단지 | 구현됨(기본 v2) | 큰 산업 수요 | 공유 병목, 비상 열 사용과 도시 약속 |

수요 묶음 하나는 한 발전원·한 경로로 전량 공급되거나 미공급된다. 병원의 현재 gate는 두 접속과
범람 시험 중 공급을 검사하지만 두 회선의 완전한 전기·공간 독립성을 증명하지 않는다. 병원 일반
부하, 내부전원과 별도 물류단지는 상용 v2에 넣지 않는다.

## 공간 레이어

| 레이어 | 상태 | 역할 |
|---|---|---|
| 건설 가능 지역 | 구현됨(기본 v2) | 점유영역 전체가 합법인 자유 좌표에 전신주·변전소 배치 |
| 강 | 구현됨(기본 v2) | 신규 설비 점유영역의 내부·경계 접촉 금지; 선로 횡단과 authored 보호기초는 허용 |
| 건물 | 구현됨(기본 v2) | 신규 설비 점유영역과 선로 관통·접촉 거부 |
| 도로 | 구현됨(기본 v2) | 지도 정체성과 공간 선택의 시각적 맥락; 별도 비용·제한 없음 |
| 서비스 연결 가능 구역 | 구현됨(기본 v2) | 변전소가 주거·산업 수요를 연결할 수 있는 기하학적 자격 |
| 위험구역 | 구현됨(기본 v2) | 초안 노출 경고와 작성된 범람·사건의 사용불가 판정 |

서비스 연결 가능 구역은 발전원이 아니다. 범위 안에 있어도 변전소에서 발전원까지 완공·사용 가능한
경로가 없거나 경로 전체의 적용 열 한도가 부족하면 공급되지 않는다.

## 건설 생명주기와 복구

```text
계획
→ 지형·위치·거리·접속 수·충돌 검토
→ 비용·공사기간과 공개 국면 preview
→ 발주와 비용 지급
→ 공사 중
→ 전체 경로 시운전
→ 완공 망 편입
```

- 독립 설비 초안은 옮기거나 취소할 수 있다.
- 선로는 마지막 초안점을 되돌리거나 전체 경로를 취소하며 중간 구간만 삭제하지 않는다.
- 공사 중 설비는 전력을 전달하지 않고, 한 공사의 모든 전신주·구간이 함께 완공된다.
- 공사 중 끝 접속점의 연결 자리는 예약되어 중복 발주할 수 없다.
- 완공 자산의 부분 편집·철거는 제외한다. 최근 완공 공사, 현재 장 또는 이전 장 시작으로 journal
  replay해 복구한다.

## 연결·공급·열 불변식

- 모든 선로 구간은 정확히 두 접속점 ID를 가지며 접속점은 형식별 최대 연결 수를 넘지 않는다.
- 공간에서 선이 교차해도 같은 접속점 ID가 아니면 연결되지 않는다.
- 신규 설비 원 전체는 지도 안에 있고 수면·건물·다른 설비 점유영역과 닿지 않는다.
- 선로는 endpoint가 아닌 제3 설비·건물을 관통하거나 접촉할 수 없다.
- 공유 선로·전신주 접속부·변전소 주기기의 사용량은 배정된 모든 수요의 합이다.
- 사용량은 적용 가능한 연속 또는 비상 한계를 넘지 않는다. 연속 초과·비상 이하 사용은 다음 국면
  보호정지를 만든다.
- 서비스 구역 부하는 선택한 변전소를 경로 끝으로 삼아 그 주기기 한계를 한 번 사용한다.
- authored 사용불가·위험구역과 현재 보호정지를 적용한 뒤 같은 공급 계산을 처음부터 다시 수행한다.
- 동일한 데이터·명령·국면은 동일한 경로·사용량·첫 실패·다음 열 상태를 만든다.

## 사건과 결과

| 사건 | 역할 | 표현 |
|---|---|---|
| 설비 하나 사용불가 | 전기적 우회 검증 | 제외 설비, 남은 경로와 공급 변화 |
| 범람·회랑 사고 | 공간적으로 함께 노출된 설비 검증 | 위험구역, 끊긴 구간과 필수서비스 결과 |
| 계획정지 | 다른 발전원과 합류망 검증 | 정지 예고, 남은 공급력과 열 병목 |
| 폭염·최대수요 | 연속·비상 한계와 다음 보호정지 검증 | 국면별 수요·경로·열 상태와 실제 결과 |

확률 고장, 상세 수리, 실시간 수동 절체와 유상 수요감축은 1.0에서 제외한다.

## 1.0에 넣지 않는 오브젝트

배터리, 원전, 석탄발전, 데이터센터, 전력시장, 대출, 다중 공사반, 사용자 switch, 부분 선로 편집과
철거는 상용 v2 1.0에 넣지 않는다. 새 오브젝트가 실제 관찰된 문제를 해결해야 할 때만 별도 권한으로
로드맵과 이 카탈로그를 함께 수정한다.
