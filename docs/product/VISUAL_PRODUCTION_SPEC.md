# Gridworks — 출시판 시각·표현 명세

이 문서는 전력망 규칙과 청류시의 이야기를 어떻게 보이게 할지 정의한다. 규칙과 수치는
[활성 계약](../scopes/RELEASE_REBUILD.md)과 출시판 데이터, 오브젝트 능력은
[카탈로그](OBJECT_CATALOG.md)가 소유한다.

기존 `ProductMain` 화면은 내부 후보의 기술 증거로 보존하지만 출시판 시각 기준이 아니다.

## 1. 표현 목표

출시판은 “낡았지만 실제로 운영되는 지역 기반시설”의 분위기를 가진다. 지도는 장식용 배경이
아니라 경로·거리·위험을 읽는 작업면이고, UI는 개발 도구가 아니라 운영센터의 정돈된 업무
화면처럼 보여야 한다.

우선순위는 다음과 같다.

1. 어디가 연결됐고 어디에서 갈라지거나 합쳐지는지 한눈에 보인다.
2. 어떤 설비가 얼마나 사용 중이고 어디에 여유가 부족한지 읽힌다.
3. 계획·공사·통전·사용불가를 색을 보지 않아도 구분한다.
4. 브리핑과 결과가 사람·서비스·원인의 순서로 읽힌다.
5. 산업적 분위기가 글과 전력망을 가리지 않는다.

## 2. 화면 구조

기본 16:9 화면은 네 영역만 사용한다.

```text
┌──────────────────────────────────────────────────────────────┐
│ 장 제목 · 날짜 · 운영 자금 · 다음 사건 · 메뉴              │
├───────────────────────────────────────┬──────────────────────┤
│                                       │ 현재 임무             │
│            청류시 전력망 지도         │ 선택 설비             │
│                                       │ 사용 / 정격 / 여유     │
│                                       │ 건설 도구와 발주       │
├───────────────────────────────────────┴──────────────────────┤
│ 상황·사건 알림 또는 짧은 원인 설명                           │
└──────────────────────────────────────────────────────────────┘
```

- 상단은 내부 단계 번호가 아니라 장 이름, 의미 있는 날짜·자금과 다음 사건만 보여준다.
- 지도는 가장 넓은 영역을 차지한다.
- 오른쪽 패널은 현재 임무와 선택 대상 하나에 집중한다.
- 하단 알림은 한 번에 세 줄을 넘기지 않는다.
- 긴 브리핑과 결과는 같은 중앙 story card를 재사용한다.

Title, Pause, Settings, Help와 확인창은 한 shell overlay에서 상호 배타적으로 연다. 새 scene stack이나
범용 modal framework는 만들지 않는다.

## 3. 촘촘한 지도

- 33×21 격자를 전체 지도 안에 고정한다.
- 한 칸 보조선은 매우 낮은 대비, 네 칸 주격자선은 조금 높은 대비로 그린다.
- 좌표 숫자는 건설 모드에서만 주격자에 표시한다.
- 평상시에는 격자를 약하게 하고 지형·시설·통전망을 우선한다.
- hover한 격자점과 마지막 계획 구간을 굵게 표시한다.
- 건설 불가 지점은 붉은 칠보다 사선 패턴과 짧은 이유를 함께 쓴다.
- 강·도로·건물 실루엣은 격자점과 선로를 가리지 않는다.

지도 확대·이동과 미니맵은 1.0에 넣지 않는다. 1280×720에서 클릭 간격과 텍스트가 충분한지 먼저
검증하고, 실제 문제가 남을 때만 범위를 다시 연다.

## 4. 지역 미술 방향

청류시는 해온강을 중심으로 서쪽 기존 전원, 북안 주거지와 정수장, 동쪽 의료원, 남쪽 산업단지가
있는 가상의 지방도시다.

- 배경: 짙은 청회색 토지, 낮은 대비의 도로·하천·필지
- 전력설비: 배경보다 선명한 청록·회백 실루엣
- 계획: 호박색 점선과 반투명 footprint
- 공사: 반복 사선과 작은 공사 표식
- 통전: 밝은 청록 실선과 느린 흐름 점
- 사용불가: 적색이 아니라도 읽히는 끊긴 선·빗금·잠금 아이콘
- 위험구역: 지도 정보를 가리지 않는 투명 패턴과 분명한 경계

주거지, 의료원, 정수장, 공장과 물류단지는 서로 다른 실루엣과 이름을 가진다. 현실 특정 도시,
게임이나 영화의 UI·건물·font를 알아볼 수 있게 복제하지 않는다.

기존 콘셉트 이미지는 분위기 참고일 뿐 출시판 화면과 수치 권위가 아니다.

## 5. 전력망 시각 문법

### 접속점

| 오브젝트 | 기본 형태 | 선택 시 정보 |
|---|---|---|
| 발전 접속점 | 굵은 모선과 발전 아이콘 | 현재 출력 / 정격, 운전 순서 |
| 일반 전신주 | 작은 원형 결절과 단순 기둥 | 연결 수, 통과 사용량 / 정격 |
| 보강 전신주 | 이중 테두리 결절 | 연결 수, 더 큰 통과 정격 |
| 배전 변전소 | 변압기 블록과 접속 모선 | 연결 수, 공급 / 정격, 연결 가능 구역 |
| 전용 수요 접속점 | 시설 아이콘 옆 계량 경계 | 요구량, 현재 공급, 공급 경로 |

분기점은 선 아래에 묻히지 않게 작은 결절을 항상 그린다. 두 선이 접속 없이 교차하면 한 선에
짧은 bridge gap을 그려 합류로 오해하지 않게 한다.

### 선로

| 상태 | 색 이외 표현 |
|---|---|
| 계획 | 점선, 낮은 불투명도 |
| 공사 | 반복 사선과 공사 표식 |
| 통전 | 굵은 실선과 느린 흐름 점 |
| 완공·무전압 | 얇은 회색 실선 |
| 사용불가 | 끊긴 실선, 빗금과 잠금 표식 |
| 선택 | 외곽선과 연결된 접속점 강조 |

선 굵기는 정격 형식에 따라 두 단계만 사용한다. 현재 사용량은 필요할 때 `1.8 / 2.5 MW`로
표시하고, 과부하처럼 보이는 애니메이션은 실제 정격 초과 상태가 없으므로 만들지 않는다. 병목은
여유가 거의 없는 설비의 외곽선과 inspector 문장으로 알린다.

## 6. 건설 피드백

선로 잇기 흐름은 다음 시각 상태를 가진다.

1. 시작 접속점 선택: 사용할 연결 자리와 현재 사용량 표시
2. 중간 전신주 preview: 거리 원, 유효·무효 위치와 다음 구간 표시
3. 끝 접속점 hover: 최종 연결 수, 전체 비용·공사기간과 예상 공급 표시
4. 계획 완료: 모든 새 전신주와 구간을 한 묶음으로 강조. 마지막 전신주 되돌리기와 전체 계획
   취소만 제공
5. 발주: 돈과 완공일 확인 뒤 공사 패턴으로 전환

거리가 너무 멀면 “전신주 사이가 너무 멉니다. 허용 거리 안에 전신주를 하나 더 세우세요.”처럼
이유와 다음 행동을 말한다. 내부 오류 코드, 좌표 정답과 추천 경로를 보여주지 않는다.

## 7. 사용량과 원인 설명

지도 overlay는 필요할 때만 켠다.

- `공급`: 살아 있는 경로와 수요처 공급 상태
- `용량`: 각 설비의 사용률과 여유
- `사고`: 제외 설비·위험구역과 살아 있는 우회

설비 inspector는 다음 순서를 지킨다.

```text
사람용 설비 이름
현재 상태
연결 3/4
사용 2.0 / 정격 2.5 MW · 여유 0.5 MW
연결된 시설 또는 공급 경로
필요한 경우 첫 문제와 해결 행동
```

공급 실패는 `전력 없음`으로 뭉개지 않는다. 예를 들어 “북안 주간선의 여유가 0.5 MW 부족해
물류단지를 공급하지 못했습니다.”처럼 첫 병목과 영향을 말한다.

## 8. 이야기 카드

시작·사건·결과는 같은 카드 구조를 쓴다.

### 시작 브리핑

- 발신자 이름과 역할
- 지금 생긴 변화
- 지켜야 할 사람·서비스
- 이번 장의 필수 목표와 다음 사건
- `지도에서 시작` 버튼

### 사건 알림

- 무엇이 시작·종료됐는가
- 어떤 설비·수요가 영향을 받았는가
- 지금 가능한 행동 또는 결과 확인

### 결과 보고

1. `임무 완료` 또는 명확한 실패
2. 병원·정수장·주거지·산업의 실제 공급 결과
3. 첫 원인과 살아남은 경로
4. 운영 자금 변화
5. 다음 장에 이어지는 망 변화

기계 식별자와 구현 단계는 카드에 나타나지 않는다. 마지막 장은 `캠페인 완료`와 청류시 전체
망의 전후 변화를 보여주는 에필로그로 끝난다.

## 9. 한국어 typography와 문체

- 한국어 본문이 깨지지 않는 번들 font 한 종류와 숫자용 같은 family weight만 사용한다.
- 본문은 한 줄 약 45자 안팎, 안내 문단은 세 줄 안팎을 목표로 한다.
- 표제·숫자·본문의 크기 단계는 세 단계만 사용한다.
- 직접 안내는 `~하세요`, 상태·결과는 짧은 평서문으로 통일한다.
- 버튼은 `대상 + 동작`으로 쓴다.
- `support`, `span`, `terminal`, `utility`, `feeder`, `LostSales`를 사용자 화면에 쓰지 않는다.
- 돈은 `운영 자금 370만`, 시간은 `2일차 06:45`, 용량은 `사용 2.0 / 정격 2.5 MW`처럼 의미를
  함께 표시한다.

한국어 표현 모듈과 캠페인 데이터가 플레이어 문구를 소유한다. Core enum·ID·예외를 문자열로
바꿔 바로 표시하지 않는다.

## 10. 접근성과 입력

- 모든 표준 버튼은 보이는 label, 접근성 이름과 keyboard focus를 가진다.
- 지도는 현재 cursor 좌표, 선택 도구와 preview 결과를 하나의 접근성 설명으로 제공한다.
- Tab·Shift+Tab으로 패널을 이동하고 화살표로 격자 cursor를 움직이며 Enter로 확정한다.
- 색만으로 계획·공사·통전·사용불가와 성공·실패를 구분하지 않는다.
- 반복 flash를 사용하지 않고 소리만으로 필수 상태를 전달하지 않는다.
- 1280×720·100%와 1920×1080·125%에서 clipping과 핵심 정보 누락이 없어야 한다.

## 11. 사운드

사운드는 정보를 보강하지만 규칙을 새로 만들지 않는다.

- ambient: 강바람, 낮은 변압기음과 먼 도시 소리
- 건설 발주: 짧은 확인음
- 통전: 차단기 투입과 낮은 상승음
- 병목 경고: 반복 alarm이 아닌 짧은 단일 신호
- 사용불가: 차단 충격과 전류음 감소
- 장 완료: 과장되지 않은 짧은 해결음

Master, Ambient, SFX 세 음량을 제공한다. 음악, 음성, 동적 믹싱과 오디오만으로 전달하는 상태는
1.0 범위가 아니다.

## 12. 제작 검수표

- 지도만 보고 분기·합류와 비접속 교차를 구분할 수 있는가?
- 선택한 전신주·선로·변전소의 연결 수, 사용량·정격·여유가 보이는가?
- 계획·공사·통전·무전압·사용불가가 색 없이도 구분되는가?
- 서비스 연결 가능 구역이 실제 공급처럼 보이지 않는가?
- 시작 카드가 이야기를 먼저, 도움말은 필요할 때 보여주는가?
- 사건 알림이 기술 변화와 사람의 영향을 함께 설명하는가?
- 결과가 성공, 공급, 원인, 돈, 다음 변화 순서로 읽히는가?
- 기계 ID, enum, 오류 코드, raw exception과 어색한 혼합 영문이 보이지 않는가?
- 1280×720·100%와 1920×1080·125%에서 글·버튼·지도 상호작용이 잘리지 않는가?
- keyboard만으로 핵심 건설·발주·결과 진행을 끝낼 수 있는가?
- 실제 패키지의 자산이 자체 제작이거나 재배포 가능한 출처·라이선스를 가지는가?
