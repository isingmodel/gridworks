# Gridworks — 2D 완성 체크리스트

> 현재 활성 구현 단계: 없음
>
> 다음 제안 단계: 첫 점등 통합본
>
> 이 체크리스트는 계획이며 구현 권한이 아니다.

상세 목표와 제외 범위는 [2D 완성 로드맵](ROADMAP_2D.md)이 소유한다. 여기에는 진행 여부와 단계
종료에 필요한 증거만 기록한다. 한 번에 한 단계만 활성화하고, 뒤 단계의 항목을 미리 구현하지
않는다.

## 체크 규칙

- `[x]`는 저장소의 현재 코드·데이터·증거로 완료가 확인된 항목이다.
- `[ ]`는 미완료 또는 미승인이다. 자세히 적혀 있어도 자동 승인된 backlog가 아니다.
- 단계 시작 전 사용자가 그 단계의 범위와 완료조건을 명시적으로 승인한다.
- 단계 종료 전 자동검사, 실제 플레이어 행동 관찰, 문서 최신화와 독립 검토를 모두 마친다.
- 기계적 사실만 PASS/FAIL로 판정한다. 사람 관찰은 `확인됨 / 문제 관찰 / 미관찰`로 기록한다.
- LLM 플레이는 남은 한 문장 상호작용 질문에 한해 최대 한 번만 별도 승인하며 반복하지 않는다.

## 현재 기반 보존

### 구현

- [x] Scope 0B 고정 시나리오의 Core, fixture, Godot 화면과 회귀검사가 있다.
- [x] Scope 1 수동 지지물 배치의 Core, fixture, 별도 Godot 화면과 회귀검사가 있다.
- [x] 서비스 권역과 실제 공급, 전기 사고와 공간 사건, 내부전원과 전력회사 공급을 분리한다.
- [x] 거리 제한, 실패 시 상태 불변, 공사 중 무전압과 원자 완공을 검사한다.
- [x] 두 구현의 데이터·규칙·화면 경계와 과거 결과를 압축 문서로 남겼다.

### 증거와 한계

- [x] 현재 fixture 식별값과 자동검사 경로가 문서화돼 있다.
- [x] 기존 LLM 관찰을 사람 사용성·재미·밸런스 증거로 해석하지 않는다.
- [x] `HumanValidationStatus = NOT_COLLECTED`를 유지한다.
- [x] 기존 두 전용 세션을 범용 제품 모델로 승격하지 않는다고 정했다.

### 종료

- [x] 현재 기반은 회귀 기준으로 동결됐다.
- [x] 다음 구현 단계는 아직 활성화하지 않았다.

## 1단계 — 첫 점등 통합본

### 활성화

- [ ] 사용자가 이 단계만 명시적으로 승인했다.
- [ ] 현재 README가 첫 점등 통합본을 유일한 활성 구현 단계로 지목한다.
- [ ] 하나의 작은 fixture와 완료조건을 구현 전에 검토했다.
- [ ] 기존 Scope 0B/1 회귀와 새 제품 경로의 경계를 확정했다.

### 플레이어 결과

- [ ] 기본 실행 장면 하나에서 기존 발전원, 배전 변전소, 마을을 볼 수 있다.
- [ ] 변전소를 허용 부지에 직접 놓을 수 있다.
- [ ] 지지물을 직접 놓아 발전원 측 terminal과 변전소를 연결할 수 있다.
- [ ] 비용·완공시각을 보고 전체 공사를 발주할 수 있다.
- [ ] 공사 중에는 마을이 무전압이고 완공 뒤에만 점등된다.
- [ ] 실제 인도 전력과 첫 매출을 결과 화면에서 확인할 수 있다.

### 구현

- [ ] 제품용 scenario authority가 한 개다.
- [ ] 제품용 Core session과 기본 Godot scene이 각각 한 개다.
- [ ] 기존 `GridworksSession`과 `Scope1PlacementSession`을 상속·일반화하지 않았다.
- [ ] Core가 부지, 충돌, 거리, 연결, 병목, 시간과 현금을 계산한다.
- [ ] Game은 pointer를 한 번 snap하고 Core preview·state만 표현한다.
- [ ] 공사 자원은 한 개이고 완공 전 설비는 공급 graph에 들어가지 않는다.

### 자동 증거

- [ ] strict fixture loader와 unknown/duplicate/missing field 검사가 통과한다.
- [ ] 부지·충돌·거리·endpoint의 경계값과 오류 우선순위를 검사한다.
- [ ] 모든 거부 명령이 상태·시간·현금을 바꾸지 않는다.
- [ ] 발주와 완공의 원자성이 통과한다.
- [ ] 서비스 권역 안이지만 무전압인 상태와 통전 상태를 모두 검사한다.
- [ ] 비용·시간·전력·판매 보존식과 결정론이 통과한다.
- [ ] 실제 map input과 standard button을 지나는 headless wiring smoke가 통과한다.
- [ ] 기존 Scope 0B와 Scope 1 회귀가 통과한다.

### 관찰

- [ ] 처음 보는 사람이 `놓기 → 연결 → 완공 → 점등`을 수행한 상태를 기록했다.
- [ ] `서비스 권역은 접속 가능 범위이고 실제 공급에는 통전 경로가 필요하다`는 이해를 기록했다.
- [ ] 관찰된 major 막힘을 수정·기능 삭제·소유자 수용 중 하나로 닫았다.
- [ ] 숫자식 사람 통과율이나 선택률 목표를 만들지 않았다.

### 종료

- [ ] 새 게임부터 첫 결과까지 한 native 장면에서 끝난다.
- [ ] 미해결 critical이 없고 모든 major의 처리가 기록됐다.
- [ ] 문서와 오브젝트 상태를 현재 구현에 맞췄다.
- [ ] 독립 검토와 수정 후 첫 점등 단계 종료를 기록했다.

## 2단계 — 발전소 직접 건설

### 플레이어 결과

- [ ] 가스발전소 한 종류를 허용 부지에 직접 놓고 발주·완공할 수 있다.
- [ ] 발전소 terminal을 선로로 연결해야만 출력과 공급이 생긴다.
- [ ] 발전소 위치가 선로 길이, 공기 또는 비용을 실제로 바꾼다.
- [ ] 자동급전 결과와 변동비를 화면에서 설명할 수 있다.

### 구현·자동 증거

- [ ] footprint, 건설영역, 겹침과 terminal 규칙이 Core에만 있다.
- [ ] 정격, 건설비·공기, 변동비와 온라인 상태가 단일 data authority에 있다.
- [ ] 미완공·미접속 발전소 출력은 0이다.
- [ ] 용량 경계, 원자 편입과 인도 전력만 매출이 되는 규칙을 검사한다.
- [ ] 첫 점등 전체 흐름과 기존 두 프로토타입 회귀가 통과한다.

### 종료

- [ ] 발전소 위치 선택이 임무 결과를 바꾼다는 관찰이 있다.
- [ ] 여러 발전 기술이나 수동급전을 추가하지 않았다.
- [ ] critical 0, major 처리, 문서 최신화와 독립 검토를 마쳤다.

## 3단계 — 유상 철거와 재구성

### 플레이어 결과

- [ ] 선택한 자산과 함께 제거될 whole-project package를 확인 전에 볼 수 있다.
- [ ] 철거비·시간·예상 미공급을 확인한 뒤 철거를 시작할 수 있다.
- [ ] 철거 뒤 장 재시작 없이 유효한 망을 다시 지을 수 있다.

### 구현·자동 증거

- [ ] 지지물 선택은 그 지지물이 속한 whole `LineProject`로 확장된다.
- [ ] 발전소·변전소 선택은 연결된 whole line package를 포함한다.
- [ ] 시작 시 package를 원자 격리하고 완료 시 graph에서 원자 제거한다.
- [ ] orphan node·span·지지물이 남지 않는다.
- [ ] 철거 거부와 preview는 상태를 바꾸지 않는다.
- [ ] 철거 뒤 미공급·현금이 일반 공급 규칙으로 정산된다.
- [ ] 부분 선로 편집, salvage·환급과 여러 공사팀을 추가하지 않았다.

### 종료

- [ ] 모든 허용 철거가 graph invariant를 보존한다.
- [ ] 재구성 전체 흐름을 실제로 한 번 확인했다.
- [ ] critical 0, major 처리, 문서 최신화와 독립 검토를 마쳤다.

## 4단계 — 두 번째 심장: 병원 신뢰도와 경제

### 플레이어 결과

- [ ] 병원 주 경로와 예비 경로를 직접 건설할 수 있다.
- [ ] 전기적 단일고장과 공간 공통회랑 사건의 영향이 다르게 보인다.
- [ ] 병원 내부전원과 전력회사 공급·판매가 별도로 보인다.
- [ ] 안전 의무를 통과한 설계끼리 기말 현금을 비교할 수 있다.
- [ ] 결과의 첫 실패 원인을 `왜?` 패널에서 확인할 수 있다.

### 구현·자동 증거

- [ ] 명시적 terminal graph reachability와 경로 병목이 결정론적이다.
- [ ] 전기 회로 경계와 공간 위험 polygon이 별도 data field다.
- [ ] 병원 UPS·디젤 사용은 전력회사 인도·판매가 아니다.
- [ ] 판매, 발전비, 보상, LostSales와 현금 보존식이 통과한다.
- [ ] 단일고장과 공간 제거의 reference oracle이 통과한다.
- [ ] 작은 authored 전략 표에 불가능한 설계와 명백한 지배전략이 없다.
- [ ] 가중 총점, 별점, 확률 고장과 전력조류 solver를 추가하지 않았다.

### 종료

- [ ] 값싼 공유회랑과 비싼 독립회랑의 서비스 결과가 실제로 다르다.
- [ ] 화면 원인과 Core 원인이 일치한다.
- [ ] critical 0, major 처리, 문서 최신화와 독립 검토를 마쳤다.

## 5단계 — 열돔 아래: 일정과 위기

### 플레이어 결과

- [ ] 타임라인에서 수요 증가, 폭염, 정비와 회선 사용불가를 미리 볼 수 있다.
- [ ] 공사·정비 순서를 정하고 중요한 경계에서 시간이 멈춘다.
- [ ] 예방정비 한 종류와 유상 공장 수요감축 한 종류를 사용할 수 있다.
- [ ] 복구 뒤 서비스와 현금 결과가 이전 선택과 연결돼 설명된다.

### 구현·자동 증거

- [ ] 정수 시각과 같은 분 사건 순서가 고정돼 있다.
- [ ] 한 공사 자원이 공사·정비를 동시에 수행하지 않는다.
- [ ] 폭염 수요 증가와 노후 회선 유효정격 감소를 각각 먼저 검산했다.
- [ ] 정비 효과, 수요감축 기간·비용, 사용불가·복구를 검사한다.
- [ ] deadline reference completion과 불가능한 일정의 안전한 거부를 검사한다.
- [ ] 사건·복구·정산에서 중복 적용이 없다.
- [ ] 확률 고장, 연속 열모델, 배터리와 상세 수리를 추가하지 않았다.

### 관찰

- [ ] 작은 전체 흐름에서 사건이 숨은 주사위가 아니라 이전 결정의 결과로 읽히는지 기록했다.
- [ ] 위기 전에 실제로 바꿀 수 있는 선택이 있었는지 확인했다.
- [ ] 선택이 결과를 바꾸지 않았다면 새 기능 대신 현재 구조를 수정했다.

### 종료

- [ ] 위기 전 선택이 서비스 또는 현금을 물질적으로 바꾼다.
- [ ] 결과 보고가 그 인과를 Core 상태와 일치하게 설명한다.
- [ ] critical 0, major 처리, 문서 최신화와 독립 검토를 마쳤다.

## 6단계 — 저장과 설정

### 플레이어 결과

- [ ] Title에서 New Game과 Continue를 선택할 수 있다.
- [ ] Pause, Save & Quit, Continue와 Restart Chapter가 작동한다.
- [ ] 창/전체화면, UI scale, 음량과 조작 도움말 설정이 유지된다.

### 구현·자동 증거

- [ ] 캠페인 저장 슬롯은 한 개다.
- [ ] 안전 경계 autosave와 임시파일 후 atomic replace를 사용한다.
- [ ] 저장 JSON은 명시적 version을 가진다.
- [ ] 모든 공사·사건 경계의 round-trip 결과가 동일하다.
- [ ] 잘린 파일, 손상 파일과 알 수 없는 version을 안전하게 거부한다.
- [ ] 손상된 저장이 새 게임 시작을 막지 않는다.
- [ ] cloud, replay, 계정, 여러 profile과 범용 migration을 추가하지 않았다.

### 종료

- [ ] 강제종료 뒤 마지막 안전 경계로 복구한다.
- [ ] 설정과 저장을 포함한 전체 회귀가 통과한다.
- [ ] critical 0, major 처리, 문서 최신화와 독립 검토를 마쳤다.

## 7단계 — 세 장 캠페인 콘텐츠

### 플레이어 결과

- [ ] `첫 점등` 장을 시작부터 결과까지 끝낼 수 있다.
- [ ] `두 번째 심장` 장을 이전 자산·현금에서 이어 끝낼 수 있다.
- [ ] `열돔 아래` 장을 이전 상태에서 이어 끝낼 수 있다.
- [ ] 각 장의 브리핑, 예보, 마감과 결과 보고가 실제 규칙과 일치한다.
- [ ] contextual tutorial과 언제든 다시 보는 도움말이 있다.

### 구현·자동 증거

- [ ] 각 장에 최소 한 개 reference completion이 있다.
- [ ] 의도된 실패와 Restart Chapter가 작동한다.
- [ ] 장 사이 carry state와 현금이 정확하다.
- [ ] 기한과 최소 공기로 완주 가능한지 검산한다.
- [ ] softlock과 중복정산이 없다.
- [ ] 콘텐츠 lock 뒤 새 mechanic을 추가하지 않았다.
- [ ] 대화 tree, cutscene, voice-over와 필수 challenge를 추가하지 않았다.

### 관찰

- [ ] 전체 캠페인의 이해, 공정성, pacing과 다시 하고 싶은 이유를 기록했다.
- [ ] 관찰을 통계적 합격률로 표현하지 않았다.
- [ ] 모든 major pacing·정보 문제를 수정·삭제·수용 중 하나로 닫았다.

### 종료

- [ ] 새 게임에서 세 장 결과까지 하나의 campaign state로 끝난다.
- [ ] 콘텐츠와 규칙을 lock했다.
- [ ] critical 0, 문서 최신화와 독립 검토를 마쳤다.

## 8단계 — 2D 출시 품질과 패키징

### 제품 표현

- [ ] 지도, 설비와 UI가 원본 2D 자산으로 교체됐다.
- [ ] 통전·계획·공사·철거·사용불가를 색 이외의 pattern·label로도 구분한다.
- [ ] 1280×720과 1920×1080 16:9에서 clipping이 없다.
- [ ] UI scale과 한국어 typography가 읽기 쉽다.
- [ ] 표준 control keyboard focus와 핵심 접근성 이름이 있다.
- [ ] 차단기·점등·사용불가와 최소 ambient SFX가 있다.

### 출시 준비

- [ ] 실제 지원할 운영체제를 확정했다.
- [ ] 지원하지 않은 플랫폼 표기를 제거했다.
