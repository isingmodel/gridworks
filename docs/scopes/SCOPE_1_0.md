# Gridworks — 1.0 후보 범위

> 상태: 미개방 제품 상한
>
> 현재 승인 단위: [Scope 0A 카드 테스트](SCOPE_0A_CARD_TEST.md)

이 문서는 첫 출시가 될 수 있는 범위를 설명하지만 backlog나 확정 로드맵은 아니다. Scope 0A가
통과해도 Scope 0B가 자동 승인되지 않고, Scope 0B가 통과해도 아래 시스템 전체가 열리지 않는다.
각 적응형 점검에서 증거가 요구하는 개발 축 하나만 다음 단위로 상세화한다.

## 1. 1.0의 제품 약속

플레이어는 기존 수요처가 있는 한 지역에서 발전소·변전소·전신주/철탑을 직접 배치하고, 인접
오브젝트 사이의 길이 한계 안에서 전선을 연결해 계통을 건설·운영한다. 완공 설비는 비용과
시간을 들여 철거하고 망을 다시 구성할 수 있다. 발전소에서 마을·병원·공장까지 실제로 전달한
MWh는 매출이 되고, 미공급 MWh는 잃은 판매와 고객등급별 보상이 된다. 병원은 선언된 단일
전기고장을 견뎌야 하며, 폭염과 예고된 설비 사용불가는 이전에 산 경로·정비·예비의 가치를
시험한다.

```text
공간에 배치한다
→ 발전원까지 연결한다
→ 공급하고 돈을 번다
→ 전기고장과 공간 공통원인이 서로 다른 약점을 드러낸다
→ 미리 산 여유와 정비가 피해를 줄인다
→ 원인·서비스·돈을 분리해 결산한다
```

출시 콘텐츠의 상한은 같은 지도 기반 최대 3장 캠페인과 고정 챌린지다. 실제 분량은 각 핵심
루프가 사람 플레이에서 검증된 뒤 결정한다.

## 2. 조건부 최소 구성

다음은 Scope 0 뒤에도 제품 가설이 살아남을 때의 **최대 최소선**이다.

- 마을·병원·공장이 있는 authored 지도 1개
- 장 시작 또는 고정 일정에 자동 발효되는 공급 의무
- 기존 grid-forming 가스발전 1기, 각각 단일 `AssetProject`로 직접 건설하는 발전소 한 종류와
  배전 변전소, 자동급전
- 직접 배치하는 한 회선 전용 degree-2 지지물 한 종류, line class 하나와 `MaxSpan` 하나
- 완공 terminal 사이를 잇는 `LineProject` 하나와 전체 경로의 원자 시운전
- 발전소·변전소·각 지지물을 선택 대상으로 하는 whole-project 유상 철거 package, 자동격리와
  연결 span 제거; 부분 line 편집 없음
- 배전 변전소 서비스 권역과 수요처별 주 공급
- 병원 독립 주·예비 경로, UPS와 비상 디젤
- 비용·공기·전기 contingency·공간 회랑이 다른 경로 선택
- 공사 자원 하나, 발주 시 전액 지불, 완공 뒤 시운전
- 실제 인도 전력 판매, 발전 변동비, 정전 보상과 수리비
- 예고된 폭염 한 종류와 노후 회선 사용불가 한 종류
- 조건부 예방정비와 위기대응 한정 수단
- authored scenario, 정수 게임 분과 재현 가능한 판정
- 지도, 상시 `왜?` 설명, 읽기 전용 선형 예고 타임라인, 사고 뒤 원인·서비스·돈 요약

이 목록도 한 번에 구현하지 않는다. 단순 graph가 선택을 충분히 표현하면 복잡한 solver를
추가하지 않는다. 한 기능이 두 개 이상의 새 가설을 동시에 열면 더 작은 prototype으로 나눈다.

## 3. 증거로 여는 개발 축

| 축 | 개방 근거 | 첫 최소 범위 |
|---|---|---|
| `Interaction` | 사용자 결정으로 1.0에 직접 지지물 배치와 거리한계가 필요함 | 고정 endpoint, 회선 전용 support type 하나, `MaxSpan` 하나 |
| `Risk/Economy` | 인과는 이해하지만 비용과 복원력 사이 유효한 비지배 선택이 없음 | 선언 stress, 안전 profile과 비용 비교 하나 |
| `Active Response` | 사전 건설만으로 위기 구간이 수동적임 | 도착시간·지속시간이 있는 조치 한 종 |
| `Scheduling` | 읽기 전용 예고만으로는 공사·정비 순서의 선택을 표현하지 못함 | 공사 자원 하나와 사건 한 쌍 |
| `Physics` | 단순 연결·병목이 메시 우회 결과를 설명하지 못함 | 고정 DC-like solver와 최소 손실 |
| `Thermal` | 과부하 지속시간이 실제 위기 결정을 만듦 | 전역 열상수 하나 |
| `Battery` | 짧은 bridge를 병원 내부전원으로 표현할 수 없음 | grid-following 저장 한 종 |
| `Generation` | 사용자 결정으로 직접 발전소 건설이 1.0에 필요함 | 유효 부지와 `AssetProject` 한 종; 포트폴리오 없음 |
| `Decommissioning` | 사용자 결정으로 유상 철거와 망 재구성이 1.0에 필요함 | whole `LineProject` 하나, 자동격리, 철거비·기간 하나 |
| `Persistence` | 세션 길이나 회귀가 저장을 실제로 요구 | 단일 JSON 저장; replay/hash는 별도 |
| `Presentation` | 지도와 `왜?` 패널로 절체·공통원인을 설명하지 못함 | 축약 결선도 또는 3D scene 중 하나 |
| `Balance Lab` | 유효 전략 3개 이상이고 손검산이 반복 개발을 막음 | knob 최대 3개의 bounded grid |

한 점검에서 축을 둘 이상 열지 않는다. 다음 축을 위한 빈 interface, schema, 저장 필드와 UI를
미리 만들지 않는다.

`Interaction`, `Generation`, `Decommissioning`은 1.0 제품 약속을 만족하려면 통과해야 하는
필수 gate다. 그러나 현재 Scope 0에 섞거나 한 번에 구현하지 않는다. 지지물 경로, 변전소 부지,
발전소 부지와 자산 철거를 각각 독립된 작은 실험으로 검증한다.

## 4. 게이트 흐름

### Gate 0A — 정보와 인과

현재 gate다. 카드로 서비스 권역/실제 연결, 전기 단일고장/공간 공통원인, 전력회사 공급/병원
내부전원을 구분하는지 검사한다. 코드는 없다.

### Gate 0B — authored causal playable

Scope 0A 통과와 별도 승인 뒤에만 연다. 고정 패드, 두 authored 회랑, 이진 공급과 한 고정
사건만 구현한다. 이 단계는 전체 재미, 경제 밸런스와 simulation 정체성을 승인하지 않는다.

### 적응형 단일축 gate

Gate 0B 결과에서 가장 큰 미검증 위험 하나를 고른다. 새 scope에는 다음이 반드시 있어야 한다.

- 한 문장 가설
- 포함과 명시적 제외
- 하나의 fixture와 숫자 권위
- 사람에게 물을 질문
- 자동검사와 오라클
- 중단조건과 다음 점검 기준

### 통합 후보

필요한 축이 개별 검증된 뒤에만 한 지도에서 세 루프를 합친다.

1. `직접 배치·건설 → 통전 → 필요시 유상 철거·재구성 → 판매`
2. `독립 경로 → 병원 절체 → 내부전원과 P0 연속성`
3. `예보 → 정비·대비 → 폭염·사용불가 → 복구·결산`

통합이 핵심 인과를 흐리면 기능을 더하지 않고 직전 단순 모델로 돌아간다. 정식 3D와 콘텐츠
양산은 그 뒤에도 별도 gate다.

## 5. 아직 결정하지 않은 승리 규칙

제품 원칙은 “필수 안전을 지킨 설계 중 경제적인 망”이지만, 어떤 스트레스까지 필수로 볼지는
아직 검증되지 않았다. 고정 script만 안전 기준에 넣으면 사건을 외운 최소망이 정답이 되고,
모든 공통원인 대비를 무조건 상위로 두면 비싼 설계가 가격과 무관하게 정답이 된다.

`Risk/Economy` gate가 열리면 아래 후보 중 하나만 사람 증거로 채택한다.

| 후보 | 장점 | 위험 |
|---|---|---|
| 필수 stress 통과 뒤 기말 현금 | 목표가 단순함 | 알려진 사건용 최소망을 장려할 수 있음 |
| 선택한 서비스 charter 안의 현금 | 위험선호를 명시함 | charter가 메타 정답이 될 수 있음 |
| 안전·복원력 profile과 현금 병렬표시 | 가중합 없이 정보 보존 | 단일 순위가 약함 |

결정 전에도 다음 원칙은 고정한다.

- 병원 P0와 돈을 한 점수로 교환하지 않는다.
- 같은 의무, 평가기간과 외부사건을 가진 설계끼리 비교한다.
- `NoBuild`를 포함한 모든 허용 설계를 전기·공간 stress matrix로 검사한다.
- 같은 채택 profile 안에서만 기말 현금을 비교한다.
- LostSales, ENS, 최대 연속정전, 복구시간과 최대 부하율을 숨기지 않는다.

경제 gate의 현금 보존식은 다음 형태를 유지한다.

```text
EndingCash = StartingCash
           - ConstructionSpend
           + DeliveredEnergyRevenue
           - GenerationVariableCost
           - ApprovedResponseSpend
           - RepairSpend
           - OutageCompensation
```

평가기간, 의무 수요 묶음과 장기자산 범위를 닫기 전에는 기말 현금을 공식 출시 순위로 쓰지
않는다. 단기 수단이 영구자산을 지배하면 금융·감가 파라미터를 추가하지 않고 임무 구조를
재검토한다.

## 6. Scheduling을 열기 위한 선행조건

`Scheduling` gate를 열기 전에 scenario 표 하나로 다음을 닫는다.

- 임무 시작·종료 `GameMinute`
- 의무 공지·활성·최초 공급기한
- 시작 자산과 설비 해금시각
- 필수 공사의 최단·최종 완료시각과 공사 자원 점유
- 정비 기간, 사건 공개, 최종 착수와 실제 사용불가 시각
- 같은 분의 공사 완료·상태 갱신·사고·계량 적용 순서

이 표에서 플레이어에게 이미 알려진 항목만 지도 구석의 선형 타임라인에 표시한다. 초기에는
모두 authored 확정시각이며, `현재 → 의무/완공 → 폭염/사용불가 → 복구` 순서를 읽게 한다.
타임라인 자체에는 drag 편집, 자동계획, 추천과 확률예측이 없다. 공장 증설 같은 수요증가는
사람 플레이가 별도 대비 사건을 요구할 때 이 gate의 단일 후보로 열 수 있다. 열 경우 요구 MW와
발효시각을 사전에 공개하고, 최소 하나의 허용 대응이 기한 전에 완료될 수 있어야 한다.

필수 완공이 불가능하거나 사건 전에 사용할 수 없는 자산을 대응안으로 보여주면 gate 실패다.
신규 발전소도 일정과 경제 검산을 모두 통과하기 전에는 1.0에 넣지 않는다.

## 7. 파라미터 예산

- Scope 0A/0B: `ActiveKnob` 0개, 자동 sweep 없음
- 사람 테스트 한 라운드: 가설 하나, 정보·구조·parameter family 중 하나만 변경
- Static Balance Lab: 개방된 경우 active knob 최대 3개
- 미래의 한 실험: 결론을 뒤집을 수 있는 `FrozenFixture + ActiveKnob` 최대 6개 family

각 입력은 `Structural / Derived / FrozenFixture / ActiveKnob / Presentation / Removed`로
분류한다. 고정값도 검증 완료가 아니며 `UnverifiedFixture / ObservedSupport / ReviewRequired`
상태를 가진다. 여러 숫자를 한 family로 묶으려면 함께 변경되는 authored 표여야 하고 scalar와
행 수를 기록한다. 한 셀을 독립적으로 바꾸면 새 family다. 여섯 family로 가설을 닫지 못하면
실험을 나눈다. 목표 A/B 선택률은 밸런스 목표가 아니다.

## 8. 1.0 명시적 제외

- 프로젝트 금융, 대출·이자·원금, 감가상각과 전력시장 입찰
- 원전·데이터센터·냉각수와 수랭↔공랭 전환
- 태양광·풍력·석탄·LNG의 동시 발전 포트폴리오
- 주민 정치, 신뢰·시위와 개별 인구 simulation
- 확률적 고장, 숨은 설비상태와 점검 정확도
- 작업반 종류·병렬공사·자재·공정 DAG와 복구 물류
- 상세 AC·무효전력·계전기 설정과 외부 solver 런타임 의존
- 절차 생성 지도, 무한경제와 본격 sandbox
- 개별 시민·교통, multiplayer, 계정과 live service

원전·데이터센터·냉각수는 [1.0 이후 방향](../future/POST_1_0.md)의 격리된 후보이며 자동 다음 단계가
아니다.

## 9. 출시 판단

자동검사는 단위, 연결, 일정, 에너지·현금 보존과 명백한 지배를 거부할 수 있다. 신규 플레이어가
망을 이해하는지, 위기를 자기 선택의 결과로 받아들이는지, 선택이 공정한지, 산업 미학이 정보를
가리지 않는지와 다시 플레이하고 싶은지는 사람만 승인한다.

각 큰 개발단위 뒤에는 구현·검사·성능·사람 증거, 예상 밖 결과와 남은 위험을 기록한다. 그
증거로 다음 단위의 가설·범위·순서·파라미터 예산·완료조건을 다시 쓰기 전에는 진행하지 않는다.
