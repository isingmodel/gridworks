# Gridworks — 출시 가능한 2D 게임 로드맵

> 문서 상태: 현재 계획

이 로드맵은 내부 테스트 후보를 실제 출시 가능한 게임으로 재구축하는 순서를 정한다. 현재 단계와
구현 권한은 루트 [README](../README.md), 정확한 규칙은
[출시판 재구축 계약](scopes/RELEASE_REBUILD.md), 진행 증거는
[체크리스트](ROADMAP_2D_CHECKLIST.md)가 소유한다.

## 1. 출발점

기존 저장소에는 세 장을 끝까지 실행하고 저장·재개할 수 있는 내부 후보가 있다. 이 후보는 건설,
서비스 범위, 병원 이중화, 발전소, 정비와 폭염의 기본 인과를 확인했다. 그러나 소유자의 전체
플레이에서 다음 출시 차단 문제가 확인됐다.

- 선로가 고정된 한 경로라 전신주·변전소의 일반적인 분기와 합류를 만들 수 없다.
- 공유 선로·분기점·변전소의 사용량이 합산되지 않아 실제 망의 용량 계획이 성립하지 않는다.
- 개발 용어, 기계 식별자와 번역투가 사용자 화면에 노출된다.
- 세 장이 실제 본편이 아니라 기능을 차례로 확인하는 튜토리얼에 가깝다.
- 21×13 격자는 경로 선택지가 성기다.

따라서 옛 제품 경로를 계속 늘리지 않는다. 과거 구현은 동결 회귀로 유지하고, 출시판은 새
그래프 Core, 새 데이터와 새 기본 장면으로 만든다.

## 2. 최종 제품

플레이어는 청류시 전력운영센터의 신임 운영책임자로서 노후한 방사형 배전망을 분기·우회 가능한
지역망으로 바꾼다. 프롤로그 세 임무에서 기본 조작을 익힌 뒤 본편 다섯 장에서 주거 확장, 공유
병목, 범람, 전원 계획정지와 폭염 비상기간을 통과한다.

출시판의 핵심 약속은 다음과 같다.

- 33×21 지도에서 기존 접속점 사이에 전신주와 선로를 직접 건설한다.
- 전신주와 변전소에서 세 갈래 이상 분기하고 다른 경로와 합류할 수 있다.
- 발전원, 선로, 전신주와 변전소의 사용량·정격·여유를 공급 결과와 함께 본다.
- 같은 망의 평상시와 설비·회랑 사고 결과가 결정론적으로 달라진다.
- 강물 위에는 새 변전소·전신주를 세우지 않되 선로는 강을 가로지를 수 있다.
- 이전 장의 자산·운영 자금과 결과가 다음 장으로 이어진다.
- 모든 안내와 결과가 자연스럽고 전문적인 한국어로 전달된다.
- 저장·재개, 장 재시작, 설정, 접근성과 설치 가능한 macOS 패키지를 제공한다.

현실성은 22.9 kV급 배전망의 연결·정격·공유 부하·우회 계획에 한정한다. 교류 전력조류,
무효전력, 보호계전과 상세 열해석은 포함하지 않는다.

## 3. 단계 1 — 분기형 배전망 기초

### 플레이어에게 만드는 기반

완공된 망이 실제 접속 그래프로 존재한다. 여러 선로가 한 전신주에서 갈라지거나 다른
전신주·변전소에서 합쳐지고, 공유 설비의 사용량이 연결된 부하의 합으로 계산된다.

### 포함

- 출시판 world 데이터와 엄격한 loader
- 발전 접속점, 전신주, 변전소, 수요 접속점과 선로 구간
- 설비별 연결 수, 통과·공급 정격, 현재 사용량과 남은 여유
- 중요도·발전 순서·안정된 식별자에 따른 결정론적 한 경로 전량 공급
- 용량 부족 우회, 낮은 우선순위 미공급과 첫 병목 원인
- 설비 하나 제거와 공간 위험구역 제거 뒤 재계산
- 33×21 격자와 대표 분기·합류·병목·우회 데이터

### 제외

Game 기본 장면, 캠페인 저장, AC/DC 전력조류, 전압강하, 자동 경로 추천, 범용 graph editor와
미래 장 UI는 만들지 않는다.

### 완료

대표 그래프 자동검사가 분기·합류, 연결 수, 공유용량, 우회, 사고와 결정성을 증명하고 기존
회귀·Game build가 유지되며 독립 P0/P1 검토가 닫히면 다음 단계로 간다.

## 4. 단계 2 — 출시판 지도와 건설 UX

### 플레이어 결과

새 기본 장면에서 촘촘한 지도를 읽고, 완공된 접속점에서 새 선로 계획을 시작해 중간 전신주를
놓은 뒤 다른 접속점에서 끝낸다. 같은 접속점에서 새 공사를 다시 시작하면 분기가 생긴다.

### 포함

- 출시판 하나의 기본 장면과 책임이 나뉜 지도·작업패널·story card
- 33×21 보조격자·주격자, 마우스 snap과 키보드 이동
- 변전소 놓기·취소, 선로 시작·중간 전신주·끝 접속점, 마지막 전신주 되돌리기·선로 계획 전체
  취소와 발주
- 계획·공사·통전·사용불가를 색과 pattern·label로 함께 표시
- 선택 설비의 연결 수, 사용량·정격·여유와 사람용 첫 실패 원인
- `상황 → 영향·이유 → 다음 행동` 순서의 한국어 표현 모듈
- 프롤로그 첫 임무를 이용한 한 번의 완전한 native 건설 흐름

### 제외

자동 배선, 카메라·미니맵, 완공 자산의 부분 철거, 새 본편 사건, 대화 트리와 localization
framework는 만들지 않는다.

### 완료

분기와 합류를 실제 지도 입력으로 만들고 공급·정격 표시가 Core와 일치해야 한다. 1280×720에서
지도와 글이 잘리지 않고 마우스·키보드 핵심 흐름을 끝낼 수 있어야 한다. 내부 영어·기계 ID·원시
예외가 노출되지 않아야 한다.

## 5. 단계 3 — 프롤로그와 본편 캠페인

### 프롤로그 세 임무

1. `첫 불빛`: 변전소, 선로와 완공 전 무전압
2. `두 번째 심장`: 병원 주·예비회선과 공간 공통원인
3. `열돔 아래`: 남부 전원 접속, 공유 용량과 서부 주간선 사용 불가 대응

세 임무는 옛 기능을 그대로 복사하지 않는다. 새 그래프·지도·문체로 짧게 다시 쓰고, 각각
본편에서 사용할 판단 하나만 익히게 한다.

### 본편 다섯 장

1. `북안 확장`: 하나의 주간선에서 주거지와 정수장으로 분기한다.
2. `공유 구간`: 산업단지 증산이 주거지·필수시설과 공유 설비 용량을 경쟁한다.
3. `범람 예보`: 고지대 우회선을 만들고 기존 망에 합류해 필수 공급을 지킨다.
4. `계획 정지`: 두 발전 접속점이 합류하는 망으로 서부 전원 정지를 견딘다.
5. `청류 비상전력`: 이전 선택을 가진 전체 망으로 최대수요와 설비 사용불가를 넘긴다.

### 이야기 전달

각 임무·장은 시작 브리핑, 사건 알림, 결과 보고 세 지점만 사용한다. 운영센터장, 계통운영관,
병원 시설책임자와 재난대응관이 기술 목표를 사람의 결과와 연결한다. 대화 선택지·호감도·컷신·
음성은 만들지 않는다.

### 진행과 복구

- 장 시작 때 고정 투자예산을 더해 앞 장의 비효율적인 성공이 영구 softlock을 만들지 않는다.
- 필수 공급·안전 의무를 지키지 못하면 원인과 `장 다시 시작`을 제공한다.
- 평상시와 사건에서 장이 요구한 수요를 공급하지 못하면 사람용 원인을 보여주고 장 시작부터
  다시 설계할 수 있다.
- 장 시작 상태, 명령 journal과 새 콘텐츠 호환 버전으로 저장·재개한다.
- 옛 내부 후보 저장은 원본을 보존하고 새 캠페인과 호환되지 않는 이유를 설명한다.

### 완료

새 저장에서 프롤로그 세 임무와 본편 다섯 장을 에필로그까지 완주하고, 각 장 대표 성공·실패,
carry-over, 저장·재개와 재시작을 자동검사한다. 본편 4장부터는 새 규칙을 추가하지 않는다.

## 6. 단계 4 — 출시 마감

### 표현

- 청류시의 강·도로·주거지·의료원·산업지대를 구분하는 원본 2D 지도
- 전신주, 변전소, 선로, 발전 접속점과 수요처의 일관된 실루엣
- 통전 흐름, 사용량·정격, 병목과 사고 상태를 읽기 쉬운 overlay
- 브리핑과 결과의 명확한 정보 위계, 한국어 typography와 의미 있는 날짜·금액 표현
- ambient와 필요한 조작·통전·사고 소리, Master/Ambient/SFX 설정

### 품질

- Title, Pause, 도움말, 설정, 한 슬롯 저장·재개와 장 재시작
- 1280×720·1920×1080에서 UI 100%·125% 대표 layout
- 마우스와 키보드 focus, 색 외 pattern·label, 소리만으로 전달하는 필수정보 0
- crash, data loss, softlock, critical과 major 0
- package 안의 credits, third-party notices, license와 설치 안내

### 사람 검토

LLM 플레이를 반복 gate로 사용하지 않는다. 자동검사와 native 회귀 뒤 한국어 원어민인 소유자가
전체 캠페인을 직접 플레이해 문체, 이야기 연결, 막힘과 화면 품질을 확인한다. 필요하면 처음 보는
외부 사람의 작은 formative play를 한 번 추가하되 통과율·선택률로 포장하지 않는다.

### 배포

저장소 밖 macOS 패키지에서 새 게임, 저장, fresh-process 재개와 전체 캠페인을 확인한다. 내부
후보 완료와 공개 배포를 구분한다. 공개 배포에는 Developer ID 서명·공증과 실제 지원 OS 확인이
필요하며, 자격증명이나 외부 권한이 없으면 그 한계와 재현 가능한 내부 후보를 정직하게 남긴다.

## 7. 공통 검증 정책

- schema, 그래프 보존식, 사용량·정격, 상태전이, 저장, build와 crash는 결정론적 자동검사로
  확인한다.
- 각 단계에서 전체 조합을 탐색하지 않고 대표 성공, 경계와 반례만 검사한다.
- native 확인은 해당 단계의 핵심 실제 입력 흐름 한 번으로 제한한다.
- LLM 관찰은 자동검사가 답할 수 없는 좁은 질문에 사용자가 별도 요청할 때만 실행한다.
- 사람의 이해·문체·재미는 관찰 기록이며 숫자식 성공률이 아니다.
- 한 단계가 끝나면 코드·데이터·증거·문서를 커밋하고 한 번의 독립 검토 뒤 다음 단계로 전환한다.

## 8. 전역 제외

1.0에는 다음을 넣지 않는다.

- 3D, sandbox, 절차 생성, 기술 트리, multiplayer와 live service
- 여러 발전기 기술을 수집하는 시스템, 배터리와 실시간 급전 조작
- AC/DC 전력조류, 전압·무효전력·보호계전과 상세 열 simulation
- 완공 자산의 부분 편집·철거와 범용 construction scheduler
- 대화 선택지, 호감도, cinematic, voice-over와 다국어 framework
- 자동 튜닝, 대규모 전략 탐색과 단계별 반복 LLM playtest

이 제외 기능이 없으면 관찰된 플레이 문제가 해결되지 않는 경우에만 로드맵을 멈추고 별도 계약을
작성한다.
