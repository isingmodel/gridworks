# Gridworks — 개발 이력 요약

이 문서는 현재 권위가 아니라 과거 결정과 교훈의 압축 기록이다. 현재 실행·단계·증거는 루트
[README](../README.md)와
[상용 2D 게임 구현 계약](scopes/COMMERCIAL_2D_IMPLEMENTATION.md), 중단된
[실시간 전면 개편 계약](scopes/REALTIME_PHYSICAL_TOTAL_REVISION.md)이 소유한다. 세부 수치·원답·
후보별 hash와 실행 기록은 동결 scope, `playtests/`와 Git 이력에 남기며 여기서 반복하지 않는다.

## 1. 카드와 작은 prototype

첫 카드 실험은 세 가지 인과를 분리해 읽을 수 있는지 확인했다.

- 변전소 서비스 권역은 접속 가능 범위일 뿐 발전원이 아니다.
- 전기적으로 다른 회로도 같은 공간 회랑에 있으면 함께 끊길 수 있다.
- 병원 내부전원과 전력회사의 공급·판매는 서로 다른 결과다.

첫 표현은 서비스 권역과 실제 공급을 충분히 구분하지 못했다. 숫자와 정답을 바꾸는 대신 질문과
정보 위계를 분리한 두 번째 표현에서 인과 설명이 개선됐다. 이 결과는 제한된 비인간 관찰이며 사람의
이해나 재미 증거가 아니다. 원본은
[`playtests/scope-0a/`](../playtests/scope-0a/)와
[`playtests/scope-0a-r2/`](../playtests/scope-0a-r2/)에 보존한다.

이어 만든 고정 병원 회랑과 수동 선로 slice는 서비스 권역·실제 경로, 전기 사고·공간 공통원인,
공사 중 무전압·원자 완공을 순수 Core와 작은 Godot 화면으로 분리했다. 초기에는 증거 절차가 제품보다
복잡해져, 실제로 끝낸 세션도 형식 때문에 무효가 되는 문제가 있었다. 이후 고정 표본과 원본 보존만
남기고 성공률·사람 사용성 주장을 버렸다. 구현·실행 기록은
[Scope 0B](scopes/SCOPE_0B_PLAYABLE.md)와
[Scope 1](scopes/SCOPE_1_INTERACTION.md)에 있다.

## 2. 첫 제품 후보와 동결 release v1

초기 제품 경로는 변전소·병원·공장·발전소·예방정비·폭염을 세 장 흐름으로 묶고 Title, 한 슬롯
저장·재개와 내부 macOS ZIP까지 연결했다. 프로젝트 소유자의 2026-08-17 전체 플레이에서 다음
출시 차단 문제가 확인됐다.

- 개발 용어와 번역투가 전문적인 한국어 제품처럼 읽히지 않았다.
- 전신주가 한 선로의 경유점에 머물러 일반 분기·합류와 공유 설비 용량을 만들 수 없었다.
- 콘텐츠가 실제 캠페인보다 긴 튜토리얼처럼 반복됐다.
- 지도가 성겨 공간 선택의 차이가 작았다.

그 뒤의 `ReleaseMain` 재구축은 33×21 격자에서 분기·합류 그래프, 공유 정격, 사건 projection,
여덟 임무, 저장·재개와 ad-hoc macOS 0.1.0 후보를 기술 기준선으로 완성했다. 당시 공식 cold LLM
한 명은 도움·재시작 없이 첫 일곱 임무를 통과했지만 마지막 임무에서 병목을 찾지 못해 중단했다.
후속 기술 수정은 경로 병목 진단, 작업 버튼 노출, 접속 한도와 수면 배치를 바로잡았다. 이 경로는
현재 제품이 아니라 동결 회귀 기준선이다. 계약과 후보 증거는
[출시판 재구축](scopes/RELEASE_REBUILD.md), [변경 기록](../CHANGELOG.md)과
[`playtests/release-2d/`](../playtests/release-2d/)에 남아 있다.

서로 다른 후보에서 수행한 이전 LLM 관찰을 합산하지 않는다. 어떤 관찰도 사람 검증, 성공률,
밸런스나 출시 승인으로 해석하지 않는다.

## 3. 상용 v2 재기획과 단계 B–G

소유자 검토와 기술 기준선의 한계를 바탕으로
[상용 2D 게임 재기획서](product/COMMERCIAL_2D_GAME_DESIGN_PLAN_KO.md)를 채택했다. v1을 계속
일반화하지 않고 별도 v2 world·campaign·Core와 `CommercialMain`을 만들었다.

- 단계 B: 보이는 격자 없는 고정소수점 자유 배치, 점유영역, 수면·건물·교차 판정과 세 단계 카메라
- 단계 C: 선로 도체·변전소 주기기·전신주 접속부의 연속·비상 한계, 보호정지와 냉각
- 단계 D: 안전 의무·도시 약속·공사 기한·국면 preview·최근 공사 복구와 save v3
- 단계 E: 같은 망을 이어 쓰는 첫 네 임무와 공통 UX
- 단계 F: 후반 네 임무, 장별 실제 결과, 약속 회수, 에필로그와 완료 저장 재개·장 재도전
- 단계 G: 관찰 기반 UX 보정, 최종 날씨·초상·사운드, settings v3·접근성과 macOS 내부 package

단계 F는 여덟 임무·에필로그를, 단계 G는 관찰 backlog와 최종 내부 후보 gate를 닫았다. G 후보는
clean commit에서 package하고 저장소 밖 빈 user-data의 두 fresh process로 전체 캠페인·완료 저장
재개·장 재설계까지 확인했다. exact 수치·hash와 marker는
[상용 구현 계약](scopes/COMMERCIAL_2D_IMPLEMENTATION.md#8-전체-완료-증거--단계-g-완료)에만 둔다.
이는 기계 규칙·저장·wiring과 내부 실행 증거이며 사람의 이해·재미·문체나 공개 출시 준비 증거가 아니다.

## 4. 단계 F 뒤 패널 수정과 공식 LLM 관찰

오른쪽 패널에 임무별 버튼이 늘며 정보 영역이 눌리던 문제는 커밋 `36038a9`에서 수정했다.
상단 정보에는 최소 200px을 보장하고, 보조 조작은 focus를 따라가는 스크롤 안에, 운영안 승인과
공사 발주는 고정 하단에 두었다. 1280×720·UI 125% smoke는 상단 정보와 스크롤된 조작의 keyboard
도달 가능성을 함께 확인한다.

이 후보를 대상으로 한 공식 cold LLM 관찰은 빈 저장의 새 게임 한 번으로 시작했다. 참가자는 앞선
임무들을 진행하면서 초안 취소 두 번과 약속 변경을 사용했고 reload, 두 번째 새 게임이나 장 되감기를
사용하지 않았다. 8장 `가장 긴 밤`의 폭염 국면 2/3에서 화면에 비상 운전 500 kW 부족이 표시된
상태로 사용자가 실행을 중단했다. 게임플레이 종료 상태는 `USER_STOPPED`이며 성공·실패·`BLOCKED`가
아니다. 에필로그에 도달하지 않았으므로 전체 완주 가능성을 판정하지 않는다.

사용자 중단 뒤 같은 참가자에게 follow-up 회고를 요청했으므로 원래의
`follow-up 없음` cold completion protocol은 `INVALIDATED_BY_USER_FOLLOWUP`이다. 게임플레이 중단
사실과 protocol 무효화를 서로 다른 상태로 남긴다. 회고는 다음 후속 과제를 제안했다.

- 최우선: 실패 수요의 발전원부터 이름 붙은 첫 병목까지 경로를 강조하고 사용·연속·비상·부족량을
  함께 표시한다.
- 최우선: 배치 입력 한 번마다 초안 반영 또는 typed 거부와 다음 행동을 즉시 확정적으로 보여준다.
- 최우선: 현재 국면 n/N과 승인 전 남은 안전 의무·약속·열 조건을 지속 체크리스트로 보여준다.
- 다음: 오른쪽 패널 위계, 밀집 대상 선택, 여러 공사의 누적 기한, hover 합법성, 국면 결과 표와
  접근성을 함께 다듬는다.
- 이후: modal을 줄이고 용어 범례를 유지하며 복구 전에 잃는 공사·시간·자금을 미리 보여준다.

이 목록은 한 LLM의 후보별 관찰에서 나온 작업 입력이며 사람 검증이나 확정 결함률이 아니다.
사용자가 별도로 연 단계 G에서 재현·보정했지만 원 관찰의 의미를 바꾸지 않는다. 공식 상태·해석 상한은
[상용 구현 계약](scopes/COMMERCIAL_2D_IMPLEMENTATION.md), task와 수용 기준은
[로드맵의 관찰 기반 backlog](ROADMAP_2D.md#관찰-기반-선행-보정-backlog--완료)가 소유한다.

## 5. 유지할 교훈과 현재 증거 상한

### 규칙과 데이터

- 한 단계에서는 한 가지 가장 큰 위험만 열고, 실행 숫자는 machine-readable authority 한 곳에 둔다.
- Core가 규칙을 계산하고 Game은 typed preview·명령 결과를 표현한다.
- 거부된 명령은 상태를 바꾸지 않으며 발주·완공은 경계에서 원자적으로 바뀐다.
- 서비스 권역, 실제 발전원 경로, 공간 위험과 열 한계를 서로 대신하지 않는다.

### 증거

- schema, 보존식, 상태전이, build, crash와 save 손상만 강한 PASS/FAIL로 판정한다.
- 이해·혼란·재미는 관찰로 기록하고 불리한 세션을 교체하거나 통과율로 포장하지 않는다.
- LLM 플레이는 자동검사가 답하지 못하는 좁은 질문에 사용자 승인으로 한 번 사용하며 사람을
  대체하지 않는다.
- 과거 후보의 성공·실패를 현재 후보에 합산하지 않는다.

현재 상용 v2에 대해 `FullCampaignHumanStatus = NOT_COLLECTED`,
`ReleaseOwnerPlayReviewStatus = NOT_COLLECTED`,
`ExternalHumanValidationStatus = NOT_COLLECTED`,
`KoreanProfessionalProofStatus = NOT_COLLECTED`다. 단계 G와 관찰 backlog는 완료했고 goal seeking을
중단했다. 단계 H 사람 검증·전문 교정·Developer ID 서명·공증·공개 배포는 미개방 상태다.

## 6. 실시간 전면 개편 R2 뒤 사용자 중단

2026-08-19~20의 별도 전면 개편은 R0 `5a9e465`, R1 실시간 Core `3da1897`을 거쳐 R2 UX
foundation·사건 지평선 구현 `4c27f65`까지 진행됐다. 마지막 exact-tree 전체 harness는 사용자가
실행 중단을 지시해 끝나지 않았으며, 그 전의 자동·native 증거를 R2 종료나 전체 개편 완료로
승격하지 않는다. R3~R7과 더 넓은 개편은 `USER_STOPPED_AFTER_R2`, 활성 revision gate는 `NONE`이다.

기본 실행은 계속 `CommercialMain`이다. 물리 UHD panel, 사람 사용성·미감, 한국어·전력설비 전문
검토와 공개 출시는 미수집·미승인 상태다. [HTML 목표 이미지](mockups/realtime-target/README.md)는
non-runtime 참고 시안이며 게임 구현, native 화면 또는 검증 증거로 합산하지 않는다.
